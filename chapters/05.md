## 1. Defining Sensitive Data

Sensitive data is any data that isn’t public or unclassified.    

### 1.1 Personally identifying information - PII. Can be used to identify an individual.    
1. See NIST 800-122 - This doc has info on PII.    
2. Can distinguish or trace an individual’s identity - ex: name, social security number, date and place of birth.    
3. Linked or linkable to an individual - ex: medical, financial, employment info.   

### 1.2 Protected health information - PHI. Any health-related info that can be related to a specific person
1. HIPAA (Health Insurance Portability and Accountability Act ).  
2. Created or received by a healthcare provider.    
3. Relates to past, present or future physical or mental health or condition of an individual.   
4. HIPAA defines PHI( Protected Health Information) more broadly.   

###  1.3 Proprietary Data.    
1. Helps an organization maintain a competitive edge.

## 2. Defining Data Classification

### 2.1 Data classification - Identifying the value of the data to the organization.

1. Critical to protect data confidentiality and integrity.   
2. Classification labels.  
3. Identifies how data owners can determine proper classification.   

#### 2.2 Government uses top secret, secret, confidential, and unclassified

1. Top secret = “exceptionally grave damage”.  
2. Secret = “serious damage”.  
3. Confidential = “damage”.  
4. Classifications also apply to physical/hardware assets.    

#### 2.3 Non-government

1. Use more meaningful labels - ex: confidential, proprietary, private, sensitive, public.   
2. More discretion.   


#### 2.4 Both systems identify relative value of data.   

1. Top secret is highest for governments.  
2. Confidential is highest for organizations.   

#### 2.5 Data Classifications.   

1. Confidential or proprietary - highest level of classified data
2. Private - Should stay private within organization
3. Sensitive - Similar to confidential, breach would cause damage to the mission of the organization
4. Public - Unclassified data
5. For the exam, remember sensitive information refers to anything that isn’t public/unclassified

#### 2.6 Defining Asset Classifications
1. If a computer is processing top secret data, the computer is a top secret asset
Same with media.  
2. Asset classification should match the data classifications.  

#### 2.7 Understanding Data States.  
1. Data at rest - Stored on media.
2. Data in transit - Data that is being transmitted over a network.   
3. Data in use - Data in memory or temporary storage while an application is using it.   
4. Protect confidentiality with strong encryption in all states.  

## 3. Handling Sensitive Information and Assets.   
Backup tapes should be protected with the same level of protection as the data that is backed up

#### 3.1 Marking Sensitive Data and Assets.  

1. Most important information that a mark or label provides is the classification of data.   
2. When users know the value of the data, they’re more likely to protect it properly based on the classification.   
3. Headers, footers, watermarks - DLP (data loss prevention) systems can identify documents that include sensitive information, apply appropriate controls.  
   Network DLP A network DLP scans all outgoing data in a traditional network looking for specific data. 
   Endpoint DLP An endpoint DLP can scan files stored on a system as well as files sent to external devices, such as printers. 
   Cloud DLP Cloud DLP is a subset of network DLP designed and tailored for cloud-native environments.
4. Use labels for unclassified media to prevent errors of omission where sensitive data isn’t marked.   
5.  If media or systems need to be downgraded to a less sensitive classification, it needs to be sanitized

#### 3.2 Storing Sensitive Data.   

1. Must store sensitive data such that it is protected against any type of loss.  
2. Most obvious protection is encryption.    
3. Do not neglect physical security practices Theft, device failure.   
4. The value of any sensitive data is much greater than the value of the media holding the sensitive data.   
5. It’s more cost effective to purchase high quality backup media than to lose sensitive data.  

#### 3.3 Destroying Sensitive Data.   

1. NIST 800-88r1 - Guides for Media Sanitization provides comprehensive details on different sanitization methods. Sanitization methods (such as clearing, purging, and destroying).   
2, Sanitization - clearing, purging, and destroying to ensure data cannot be recovered by any means
When a computer is disposed of, sanitization means all nonvolatile memory is removed/destroyed. 

#### 3.4 Eliminating Data Remanence.   

1. Data remanence - Data that remains on media after the data was supposedly erased.   
2. Degausser - Generates heavy magnetic field to destroy data. Cannot degauss SSDs (solid state drives).Best method of sanitizing SSDs is destruction.  
3. Erasing - Performing a delete operation against a file. Only removes the directory or catalog link to data.The data remains on the drive.    
4. Clearing - AKA overwriting. Prepares media for re-use. Unclassified data is written over all addressable locations on the media. Maybe writing a single character or bit pattern over all media. It is still possible to retrieve some of the original data using lab or forensics.   
5. Purging - More intense form of clearing. Prepares media for reuse in less secure environments. The only method for reuse in less secure environments. Repeats the clearing process multiple times and may combine with other methods like degaussing to completely remove data.   
6. Destruction - Most secure method of sanitization. Data cannot be extracted from destroyed media.  
7. Declassification - Any process that purges media or a system to prepare it for use in an unclassified environment.  
8. Sanitization methods are often more effort than the cost for new media.  
9. Purging memory buffers remove all remnants of data after a program has used it.  

#### 3.5 Ensuring Appropriate Asset Retention. 

1. Record retention involves retaining and maintaining important information as long as it is needed and destroying it when it is no longer needed. 
2. Record retention and media retention is the most important part of asset retention.  
3. Record retention - Maintaining important information as long as it is needed, destroying when it isn’t.  
4. Companies cannot legal delete potential evidence after a lawsuit is filed.  

#### 3.6 Data Protection Methods.  

1. Digital rights management (DRM) methods attempt to provide copyright protection for copyrighted works.  
2. DRM License A license grants access to a product and defines the terms of use. A DRM license is typically a small file that includes the terms of use, along with a decryption key that unlocks access to the product.  
3. Persistent Online Authentication Persistent online authentication (also known as always-on DRM) requires a system to be connected with the Internet to use a product.   
4. Continuous Audit Trail A continuous audit trail tracks all use of a copyrighted product.   
5. Automatic Expiration Many products are sold on a subscription basis.  
6. A cloud access security broker (CASB) is software placed logically between users and cloud-based resources. It can be on-premises or within the cloud. Anyone who accesses the cloud goes through the CASB software. 
7. Pseudonymization - Pseudonymization refers to the process of using pseudonyms to represent other data. it can result in less stringent requirement (GDPR). The GDPR refers to pseudonymization as replacing data with artificial identifiers.  
8. Tokenization is the use of a token, typically a random string of characters, to replace other data. It is often used with credit card transactions, this invovles steps. - Registraion, Usage, Validation and Completing the sale.  Example (The payment network sent the credit card number to a tokenization vault controlled by the payment network or a third-party service provider. The vault created a token (a string of characters) and recorded the token along with the encrypted credit card number). 
9. Anonymization is the process of removing all relevant data so that it is theoretically impossible to identify the original subject or person.
10. Anonymization techniques remove all personal data and make the data unusable for reuse on the website. Pseudonymization replaces data with pseudonyms or artificial identifiers. Although the process can be reversed, it is not necessary.  
11. Scoping is a part of the tailoring process and refers to reviewing a list of security and privacy controls and selecting the controls that apply. 


### 4 Understanding Data Roles.  

#### 4.1 Data owner.  

1. The person who has ultimate organizational responsibility for data. Establishes rules for appropriate use and protection.  
3. Input regarding security requirements and controls.  
4. Decides who has access to information and with what privileges.  
5. Assists in the identification and assessment of security controls.  
6. NIST 800-18.  
7. Uses phrase “rules of behavior” which means Acceptable Use Policy.  

#### 4.2 Data Processors

1. Data processor - Any system used to process data. A data controller decides what data to process and how. 
2. GDPR defines as a “natural or legal person, public authority, agency, or other body, which processes personal data solely on behalf of the data controller. Data controller controls the processing of data.  
4. EU-US Privacy Shield.  
5. Swiss-US Privacy Shield.  
6. Privacy Shields are deep, but include.  
7. Notice - Organization must inform individuals about the purpose of data it collects.  
8. Choice - Offer a chance to opt out of data collection.  
9. Accountability for onward transfer - Can only transfer data to other organizations that comply with notice and choice principles.  
10. Security - Take reasonable precautions to protect personal data. 
11. Data integrity and purpose limits - Should only collect data that is needed for purposes in the notice
12. Access - Individuals must have access to information an organization holds about them, and to correct, amend or delete it.  
13. Recourse, enforcement and liability - Must implement mechanisms to ensure compliance and handle complaints. These are also general GDPR principles.

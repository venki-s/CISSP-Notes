## 1. Asymmetric Crypography.   

### 1.1 Public and Private Keys.  

1. Every user maintains a public key and a private key in asymmetric crypto.  
2. Private key is preserved for the sole use of the individual who owns the key.  
3. Public key is available to anyone they want to communicate with. 

#### 1.1.1 RSA. 
1. Choose two large prime numbers approximately 200 digits each labeled p and q.  
2. Multiply them together n = p * q.  
3. Select a number e that is:  
   a. Less than n
   b. e and (p - 1)(q - 1) are relatively prime (no common factors)
4. Find d that is (ed - 1) mod (p - 1)(q - 1) = 1.  
5. Distribute e and n as the public key and keep d as the secret private key. 


4. Key length is the most important parameter.  
   a. RSA key length: 1024 bits.    
   b. DSA key length: 1024 bits.  
   c. Elliptical curve key length: 160 bits.  
5. El Gamal Major disadvantage - this algo doubles the length of any message it encrypts.   
6. Elliptical Curve.  
   a. Better for low power devices like phones.   
   b. 1024 bit RSA key is cryptographically equivalent to 160 bit elliptical curve.  
7. The Diffie–Hellman key exchange algorithm relies on the use of large prime numbers. The ECDHE (Elliptic Curve Diffie-Hellman Ephemeral) key exchange algorithm is a variant of this approach that uses the elliptic curve problem.     
8. FIPS 186-5 - NIST specifies the digital signature algorithms acceptable for federal government use in FIPS 186-5, also known as the Digital Signature Standard (DSS). There are three currently approved standard encryption algorithms in FIPS 186-5: RSA, The Elliptic Curve Digital Signature Algorithm (ECDSA), and The Edwards Curve Digital Signature Algorithm (EdDSA).  



### 1.2 Hash Functions.  
1. Hash functions - Take a potentially long message and generate a unique output value derived from the content of the message.  
2. Message digest - The output of a hash function.  
3. Basic hash function requirements.  
   a. Input can be any length.  
   b. Output has a fixed length.  
   c. Should be relatively easy to compute for any input.  
   d. Hash function is one-way which means it is extremely hard to determine the input when provided the output.   
   e. Collision free - hard to find two inputs that produce the same message digest.  
4. SHA - Secure Hash Algorithm.  
5. SHA-1 produces 160 bit digest.  
6. Processes 512 bit blocks.  
7. Pads messages to fit.  
8. SHA-256 produces 256 bit messages using 512 bit block size.  
9. SHA-224 uses truncated version of SHA-256 hash to make a 224 bit message with 512 bit block size.  
10. SHA-512 produces 512 bit message digests using a 1024 bit block size.  
11. SHA-384 uses truncated SHA-512 to produce 384 bit digest with 1024 bit block size. 

### 1.3 MD5.  
1. 512 bit blocks.  
2. 4 distinct rounds of computation.  
3. Message length must be 64 bits less than a multiple of 512 bits.  (64 bits are be reserved)
4. Uses padding to make up the difference. 
5. Hash of Variable Length (HAVAL) - MD5 variant.  
6. Hash value length: 128, 160, 192, 224, 256 bits.

### 1.3 Digital Signatures.   

1. Enforces nonrepudiation. 
2. Assures the recipient that the message was not altered while in transit. 
3. Does not provide privacy/confidentiality.  
4. Does provide integrity, authentication, nonrepudiation.  
5. HMAC - Hashed Message Authentication Code.  
   a. Provides integrity, does not provide nonrepudiation.  
   b.  Depends on a shared secret key.  
6. Digital Signature Standard Federal Information processing Standard (FIPS) 186-4

### 1.4 Public Key Infrastructure.  

#### 1.4.1 Certificates.   
1. Endorsed copies of a public key. 
2. International standard: X.509. 
3. Contains. 
   a. Version of X.509 it conforms to.  
   b. Serial number. 
   c. Signature algo identifer. 
   d. Issuer name.  
   e. Validity period.  
   f. Subject’s name. 
   g. Subject’s public key.  
4. Certificate extensions are custom variables inserted into a certificate.  
5. Certificate Authorities.  
   a. Neutral organizations that offer notarization services for digital certificates.  
   b. Registration authorities assist by verifying user’s identities prior to issuing certificates but do not issue certs themselves.  
   c. Certificate Path Validation - CPV. Each certificate in the certificate path from the original start or root of trust down to the server or client in question is valid and legitimate.   
6. Certificate Generation and Destruction.  
7. Enrollment.  
   a. Prove your identity to the CA.  
   b. Provide them your public key.  
   c. CA signs your certificate with their private key. 
8. Verification.  
   a. Verify the cert by checking the CA’s digital signature using the CA’s public key
   b. Make sure it was not revoked (Certificate Revocation List - CRL) Or Online Certificate Status Protocol (OCSP)
9 A certificate is valid if:   
   a. The digital signature of the CA is authentic.  
   b. You trust the CA.  
   c. The certificate is not listed on a CRL.  
   d. The certificate contains the data you are trusting.  
10. Revocation.  
   a. Revoking a certificate declares it invalid before it’s natural expiry.  
   b. Certificate Revocation Lists (CRLs) contain serial numbers of certs that a CA revoked along with when they were revoked.  
   c. Online Certificate Status Protocol (OCSP) eliminates latency with CRLs by providing a real-time check. 
11. The most common binary format is the Distinguished Encoding Rules (DER) format. DER certificates are normally stored in files with the .der, .crt, or .cer extension.
12. The Privacy-Enhanced Mail (PEM) certificate format is an ASCII text version of the DER format. PEM certificates are normally stored in files with the .pem or .crt extension.  
13. The Personal Information Exchange (PFX) format is commonly used by Windows systems. PFX certificates may be stored in binary form, using either .pfx or .p12 file extensions.
14. Windows systems also use P7B certificates, which are stored in ASCII text format using the .p7b file extension.



### 1.5 Asymmetric Key Management. 
1. Choose an encryption system whose algo is in the public domain. 
2. Use a key length that balances security requirements with performance.  
3. Keep private key secret. 
4. Retire keys when they’re done being useful. 
5. Back up your key. 
6. Hardware security modules - HSMs. Store and manage encryption keys in a secure manner. 
Yubikey is an example. 

### 1.6 Applied Cryptography. 
1. Portable devices - Current versions of popular operating systems now include disk encryption capabilities that make it easy to apply and manage encryption on portable devices. 
2. Windows includes BitLocker and Encrypting File System (EFS).  
3. Mac has FileVault.  
4. Linux has VeraCrypt.  
5. All for disk encryption of mobile devices like laptops
6. Trusted Platform Module - TPM. A chip on the motherboard that stores and manages keys used for full disk encryption.

#### 1.6.1 Email.  
1. For confidentiality, encrypt the message. 
2. For integrity, hash the message.  
3. For authentication, integrity, and/or nonrepudiation, digitally sign the message.  
4. For confidentiality, integrity, authentication, and nonrepudiation, encrypt and sign the message.  
5. Always the responsibility of the sender.  
6. Pretty Good Privacy - PGP.  
   a. “web of trust”.  
   b. Secure email system.  
7. Secure/Multipurpose Internet Mail Extensions - S/MIMEUses X.509 certificates for exchanging crypto keys. 

#### 1.6.2 Web Applications
1. SSL and TLS (Secure Sockets Layer, and Transport Layer Security).  
2. HTTPS (Hypertext Transfer Protocol Secure) uses port 443 to negotiate encrypted communications between web servers and clients.  
3. Depends on the exchange of server digital certificates.  
   a. When a user accesses a website, the browser gets the web server’s cert and extracts the public key from it
   b. The browser creates a random symmetric key, uses the server’s public key to encrypt it, and sends the encrypted symmetric key to the server.  
   c. The server decrypts the symmetric key using it’s private key, and the two systems exchange future messages using symmetric encryption/key. 
4. Padding Oracle On Downgraded Legacy Encryption (POODLE) is a downgrade attack - forcing a system to use an older/vulnerable version of TLS or SSL instead of an up to date version.  

#### 1.6.3  Steganography and Watermarking.  
1. Steganography - Using crypto techniques to embed secret messages within another message. 
2. Ex: Adding digital watermarks to documents to protect intellectual property.  

### 1.7 Networking. 
1. IPSec and Internet Security Association and Key Management Protocol (ISAKMP).  

#### 1.7.1 Circuit Encryption.  
1. Link encryption - Protects entire communication circuits by creating a secure tunnel
2. End-to-end encryption - Protects communications between two parties
3. The difference between the above is that link encryption, all data including headers, trailers, address, routing data is also encrypted
4. When encryption happens at higher OSI layers, it’s usually end-to-end
5. Secure Shell - SSH. End-to-end encryption

#### 1.7.2 IPsec.  
1. IPSec is a standard architecture set forth by the Internet Engineering Task Force (IETF) for setting up a secure channel to exchange information between two entities.
2. Could be any two entities - servers, routers, gateway, a combo. 
3. Uses public key crypto to provide encryption, access control, nonrepudiation, message authentication
4. VPNs use IPSec.  
5. Authentication Header - AH. provides message integrity and nonrepudiation. 
6. Encapsulating Security Payload - ESP. Provides confidentiality and integrity of packet contents. 
7. Transport mode - only the packet payload is encrypted. 
8. Tunnel mode - entire packet, including header, is encrypted. 

#### 1.7.3 Wireless networking
1. Wired Equivalent Privacy - WEP. 64 bit and 128 bit encryption for IEEE 802.11. 
2. A lot of flaws exist here, not considered secure - should never be used.  
3. WiFi Protected Access - WPA. Improves WEP by adding Temporal Key Integrity Protocol (TKIP)
4. WPA2 adds AES crypto , butDoes not provide end-to-end encryption.  
5. 802.11x - authentication and key management framework for both wired and wireless networks Client runs software called a supplicant. 

### 1.8 Cryptographic Attacks.  
1. Analytic Attack - Using math to reduce complexity of algo
2. Implementation Attack - Exploits weaknesses in the implementation of a crypto system
3. Statistical Attack - Using math to find patterns, floating-point errors, inability to find truly random numbers
4. Brute Force - Trying every possible combination for key and password
5. Key length is critical for defending brute force
6. Rainbow tables - precomputed values for crypto hashes, commonly for cracking passwords
7. Salt - A random value added to the end of the password before it is hashed
8. Frequency analysis - Counting the number of times each letter appears in the ciphertext
9. Known Plaintext - Attacker has a copy of the encrypted message, along with plaintext, can be used to determine the key
10. Chosen Ciphertext - Attacker chooses plaintext, obtains its ciphertext, and analyzes it to discover the key. Attacker has ability to decrypt portions of the ciphertext
11. Chosen Plaintext - Attacker chooses ciphertext, obtains its decrypted plaintext, and analyzes it to discover the key. Attacker has ability to encrypt plaintext messages of their choosing
12. Meet in the Middle - Known plaintext message. Breaks double encryption by encrypting known plaintext with possible keys and decrypting ciphertext with possible keys until they match.
13. Man in the Middle - A malicious individual sits between two communicating parties and intercepts communications
14. Birthday - AKA collision attack, finding flaws in hashing functions where two inputs generate the same output
15. Replay - A system lacks temporal protections, a message can be sent more than once at different times. In this attack, the malicious individual intercepts an encrypted message between two parties (often a request for authentication) and then later “replays” the captured message to open a new session.
16. Side-channel attacks use information gathered about a system's use of resources, electricity consumption, timing, or other characteristics to contribute to breaking the security of encryption.

## 1. OSI Model

### 1.1 OSI Functionality.  

1. Know the different levels of the OSI model in order
   a. Application (7)
   b. Presentation
   c. Session
   d. Transport
   e. Network
   f. Data Link
   g. Physical (1)
2. Come up with a pneumonic device to remember them if you have to - All People Seem To Need Data Processing, for instance
3. Encapsulation/Deencapsulation - The addition of a header and maybe a footer to the data received by each layer from the layer above it before it’s handed off to the layer below, and then the subsequent removal of those headers and footers and the received data flows back up the OSI model on the other end. Any protocol at any OSI layer can define a header, a trailer (footer), or both.
4. Pieces of data have different names at different points in the OSI model.  
   a. Application/Presentation/Session Protocol data unit - PDU.  
   b. Transport Layer - Segment(TCP) or datagram(UDP) - Transport layer data units.
   c. Network layer - Packet.    
   d. Data link layer - Frame. 
   e. Physical layer - Bits. 
5. Encryption in relation to network communication can occur in at least five locations:
   a. Pre-network encryption, where the software encrypts prior to sending the data into the Application Layer
   b. Transport Layer encryption typically performed by TLS
   c. VPN encryption, which can occur at Layer 2, 3, or 4 depending on the VPN technology in use 
   d. Wireless encryption at the Data Link Layer
   e. Bulk encryption at the Physical Layer

### 1.2 Application Layer.   

1. Interfacing user applications, network services, or the OS with the protocol stack. 
2. The application is not located at this layer, the protocols and services required.

### 1.3 Presentation Layer.  
1. Transforms data from the application layer into a format that any system using the OSI model can understand.  
2. Images, video, sound, ASCII, JPEG, etc.  

### 1.4 Sessoion Layer.  
1. The Session Layer (Layer 5) is responsible for establishing, maintaining, and terminating communication sessions between two computers.  
2. Communication sessions
   a. Simplex: One-way communication (as a sender or receiver, but not both)
   b. Half-Duplex:  Two-way communication, but only one direction can send or receive data at a time
   c. Full-Duplex:  Two-way communication, in which data can be sent and received in both directions simultaneously

### 1.5 Transport Layer.

1. The Transport Layer is responsible for managing the integrity of a connection and controlling the session. 2. The Transport Layer establishes communications between nodes (also known as devices) and defines the rules of a session. 
3. Session rules specify how much data each segment can contain, how to verify message integrity, and how to determine whether data has been lost. Session rules are established through a handshaking process.
4 Protocols
  a. Transmission Control Protocol (TCP)
  b. User Datagram Protocol (UDP)

### 1.6 Network Layer. 
1. Adding routing and addressing information to data. 
2. Internet Group management Protocol (IGMP) - Multicast protocol. 
3. The three most recognized non-IP protocols are IPX, AppleTalk, and NetBEUI. 
4. Routers and bridge routers function at layer 3. 
5. Routing protocols. 
   a. Distance vector - keep a list of destination networks along with metrics of direction and distance measured in hops. 
   b. Link state - keep a topography map of all connected networks and use this map to determine the shortest path to a destination network. 
   c. Path vector - Path vector routing protocols make next hop decisions based on the entire remaining path (i.e., vector) to the destination.  

### 1.7 Data Layer. 
1. The Data Link Layer (Layer 2) is responsible for formatting the packet for transmission.  
2. The proper format is determined by the hardware, topology, and technology of the network, such as Ethernet (IEEE 802.3).  
3. Network hardware devices that function at Layer 2, the Data Link Layer, are switches and bridges. These devices support MAC-based traffic routing.  
4. Media Access Control address - MAC address, 48 bit binary address that identifies a device
First 3 bytes of the address denotes the vendor or manufacturer of the physical network interface.  

### 1.8 Physical Layer. 
1. Converts the frame into bits for transmission over the physical connection medium.  
2. Network hardware devices that function at Layer 1, the Physical Layer, are NICs, hubs, repeaters, concentrators, and amplifiers.  


## 2. TCP/IP.   

### 2.1 TCP/IP Model. 

1. The TCP/IP model (also called the DARPA model or the DOD model) consists of only four layers. 
2. The four layers of the TCP/IP model are 
   a. Application/Process (Application, Presentation, Session). 
   b. Transport/Host-to-host (Transport). 
   c. Internet/Internetworking (Network).  
   d. Link/Network Interface (Data link and Physical). 
3. Improperly implemented TCP/IP stacks in various operating systems are vulnerable to buffer overflows, SYN flood attacks, various denial-of-service (DoS) attacks, fragment attacks, oversized packet attacks, spoofing attacks, adversary-in-the-middle attacks (AitM), hijack attacks, and coding error attacks.  

### 2.2 Analysing network Traffic. 

1. A protocol analyzer/sniffer/network evaluator/network analyzer/traffic monitor/packet-capturing utility is a tool used to examine the contents of network traffic. It can be a hardware or software. A protocol analyzer is a frame/packet-capturing tool that can collect network traffic and store it in memory or on a storage device. 
2. A protocol analyzer usually places the NIC into promiscuous mode to see and capture all Ethernet frames on the local network segment. In promiscuous mode, the NIC ignores the destination MAC addresses. The protocol analyzer can examine individual frames down to the binary level. 
3. Protocol analyzers typically offer both capture filters and display filters. A capture filter is a set of rules to govern which frames are saved into the capture file or buffer and which are discarded. A display filter is used to show only those frames from the packet file or buffer that match your requirements.

### 2.4 Common Network Protocols and Ports

1. **Telnet — TCP 23:** Remote command-line access; insecure. Use SSH (22).

2. **FTP — TCP 21 (Control), 20 (Active Data):** File transfer; insecure. Passive mode uses negotiated data ports. Use SFTP or FTPS.

3. **TFTP — UDP 69:** Simple file transfer without authentication; commonly used for network device configurations.

4. **SMTP — TCP 25:** Sends emails between mail servers.
   - TCP 587 — Email submission with STARTTLS.
   - TCP 465 — Email submission with implicit TLS.

5. **POP3 — TCP 110:** Downloads emails from a mail server.
   - TCP 995 — Secure POP3 (POP3S).

6. **IMAP4 — TCP 143:** Accesses and manages emails on the mail server.
   - TCP 993 — Secure IMAP (IMAPS).

7. **DHCP — UDP 67 (Server), 68 (Client):** Automatically assigns IP addresses and network settings.

8. **HTTP — TCP 80:** Transfers web pages without encryption.

9. **HTTPS — TCP 443:** Secure web communication using TLS.

10. **LPD — TCP 515:** Sends and manages network printer jobs.

11. **X Window — TCP 6000–6063:** Supports remote graphical interfaces; secure access recommended.

12. **NFS — TCP 2049:** File sharing across networked systems; secure access recommended.

13. **SNMP — UDP 161 (Queries), 162 (Traps):** Monitors network devices and receives alerts. Use SNMPv3.


### 2.5 Transport Layer Protocols. 
1. Ports 0 through 65535. 
2. Well known ports: 0 - 1023. 
3. Registered ports: 1024 - 49151. 
4. Random, dynamic, ephemeral ports: 49152 - 65535. 
5. Transport Control Protocol - TCP. 
   a. Connection oriented. 
   b. Reliable sessions. 
   c. Handshake process. 
6. TCP Connection steps. 
   a. Client sends a SYN packet to server. 
   b. Server responds with SYN/ACK to client. 
   c. Client responds with ACK to server. 
   d. Uses FIN packets to terminate connections. 
   e. Uses ACK packets to confirm that data has been received. 
   f. Uses RST packets to forcibly close connections.  
   g. Uses a graceful 4 packet teardown. 
   h. Each side sends a FIN. 
   i.Each side ACKs the FIN sent by the other. 
7. IP protocol header field value for TCP is 6. 
8. User Datagram Protocol - UDP. 
   a. Connectionless, best effort. 
   b. Considered unreliable. 


### 2.6 Network Layer Protocols and IP Basics

- **IP:** Logical addressing and packet routing.
- **IPv4:** 32-bit | **IPv6:** 128-bit.
- **IP Classes:** A, B, C = Unicast; D = Multicast; E = Reserved.
- **Loopback:** 127.0.0.1.
- **CIDR:** Slash notation for network prefixes (e.g., /24).

- **ICMP:** Network diagnostics and error reporting (ping).
  - Attacks: Ping of Death, Smurf, Ping Flood.
- **IGMP:** Manages IPv4 multicast groups.
- **ARP:** Resolves IPv4 addresses to MAC addresses.
  - Security risk: ARP spoofing/poisoning.

- **Unicast (One-to-One):** Sends data to one device. Example: Browsing a website.
- **Broadcast (One-to-All):** Sends data to all devices on a local network. Example: ARP request.
- **Multicast (One-to-Group):** Sends data to selected devices in a group. Example: Live video streaming to subscribed receivers.


## 3. Domain Name System (DNS). 

- **DNS:** Translates domain names into IP addresses.
- **ARP:** Translates IPv4 addresses into MAC addresses.
- **DNS Ports:** UDP 53 (normal queries), TCP 53 (zone transfers and some larger responses).

### 3.1 DNS Naming.  

Example: `www.google.com`. 
- **TLD:** `.com`. 
- **Registered Domain:** `google`. 
- **Hostname/Subdomain:** `www`.  
- **FQDN:** Complete domain name (`www.google.com`).

### 3.2 DNS Servers and Records. 

- **Primary Authoritative Server:** Maintains the original, editable DNS zone file.
- **Secondary Authoritative Server:** Maintains a read-only copy of the zone file.
- **Zone File:** Collection of DNS resource records.

**Important DNS Records:**
- **A:** Domain → IPv4 address.
- **AAAA:** Domain → IPv6 address.
- **PTR:** IP address → Domain (Reverse DNS).
- **CNAME:** Domain alias → Another domain name.
- **MX:** Mail server for a domain.
- **NS:** Authoritative name server.
- **SOA:** Zone authority and administrative information.

### 3.3 DNS Security. 

- **DNSSEC:** Uses digital signatures to verify DNS data authenticity and integrity; does not encrypt DNS traffic.
- **DoH (DNS over HTTPS):** Encrypts DNS queries using HTTPS/TLS.
- **ODoH (Oblivious DoH):** Adds a proxy to improve DNS query privacy.

### 3.4 DNS Attacks. 

- **DNS Poisoning:** Inserts false DNS information into DNS records or caches.
- **DNS Spoofing:** Sends forged DNS responses to redirect users.
- **Rogue DNS Server:** Malicious DNS server providing false IP addresses.
- **Pharming:** Redirects users from legitimate websites to fake websites using DNS or hosts-file manipulation.
- **Domain Hijacking:** Unauthorized takeover of domain registration.
- **Homograph Attack:** Uses lookalike characters in fake domain names to deceive users.

### 3.5 DNS Protection. 

- **DNSSEC:** Protects DNS data authenticity and integrity.
- **Split DNS:** Separates internal and external DNS servers to protect internal DNS information.
- **DNS Sinkhole:** Redirects malicious DNS requests to controlled or blocked destinations.
- **Restrict Zone Transfers:** Prevents unauthorized access to DNS zone information.
- **Monitoring:** Use IDS and DNS logs to detect suspicious DNS activity.
- **Domain Protection:** Use MFA and auto-renewal for domain registrations.

## 4. Internet Protocol (IP) Networking. 

1. Some of IPv6's new features are scoped addresses, autoconfiguration, and quality of service (QoS) priority values.
2. Autoconfiguration theoretically removes the need for traditional DHCP and network address translation (NAT). However, DHCPv6 and NAT66 exist 
3. DHCPv6 has two modes of operation. In stateful mode, DHCPv6 assigns specific IPv6 addresses to devices and manages the allocation of network configuration parameters. In stateless mode, DHCPv6 provides network configuration parameters without assigning specific IPv6 addresses. 
4.SLAAC is based on routers periodically sending Router Advertisement (RA) messages to the local network segment. 
5. The loopback address for IPv4 is any address in the Class A subnet of 127.0.0.1–127.255.255.254, even though only the address of 127.0.0.1 is typically used. 
6. Internet Control Message Protocol (ICMP) is used to determine the health of a network or a specific link. ICMP is utilized by ping, traceroute, tracert, pathping, and other network management tools. 
7. Internet Group Management Protocol (IGMP) allows systems to support multicasting. Multicasting is the transmission of data to multiple specific recipients.

## 5. ARP Concerns
1. Address Resolution Protocol (ARP) is used to resolve IP addresses (32-bit binary number for logical addressing) into MAC addresses 
2. ARP cache poisoning or ARP spoofing is caused by an attacker responding with falsified replies. 
3. Another form of ARP poisoning uses gratuitous ARP or unsolicited ARP replies. This occurs when a system announces its MAC-to-IP mapping without being prompted by an ARP query. 
4. A third form of ARP cache poisoning is to create static ARP entries.
5. The best defense against ARP-based attacks is port security on the switch. 
6. Another defense is to establish static ARP entries. Yes, this can be used as both an attack/abuse and a defense. However, this is not often recommended because it removes the flexibility of a system adapting to changing network conditions, such as other devices entering and leaving the network.

## 6. Secure Communication Protocols. 

1. IPSec Internet Protocol Security (IPSec) uses public key cryptography to provide encryption, integrity, antireplay, access control, and message origin authentication, all using IP-based protocols.
2. Kerberos Kerberos offers a single sign-on (SSO) solution for users and provides protection for logon credentials. 
3. SSH Secure Shell (SSH) is a good example of an end-to-end encryption technique.
4. Signal Protocol This is a cryptographic protocol that provides end-to-end encryption for voice communications
5. Secure Remote Procedure Call (S-RPC) S-RPC is an authentication service for cross-network service communications 

## 7. Converged Protocols 


### 7.1 Converged Protocols.  

- **Converged Protocols:** Combine specialized services with standard networking technologies (such as TCP/IP), reducing the need for separate network infrastructure.

- **SAN (Storage Area Network):** Dedicated storage network that provides shared storage to multiple servers.
  - **Risk:** Single point of failure; requires redundancy.
  - **Deduplication:** Eliminates duplicate data to save storage space.

- **iSCSI:** Enables access to storage over IP networks; lower-cost alternative to Fibre Channel.
- **InfiniBand over Ethernet (IBoE):** Carries high-performance InfiniBand traffic over Ethernet.
- **CXL (Compute Express Link):** High-speed interconnect between CPUs, GPUs, accelerators and memory.

### 7.2  Voice over IP (VoIP)

- **VoIP:** Transmits voice and multimedia communications over IP networks.
- **SIP (Session Initiation Protocol):** Establishes and manages communication sessions.
- **RTP (Real-Time Transport Protocol):** Carries real-time audio/video.
- **SRTP (Secure RTP):** Provides encryption and authentication for RTP communications.

**VoIP Security Risks:**
- **Vishing:** Voice phishing through phone calls.
- **SPIT:** Spam over Internet Telephony.
- **Eavesdropping:** Interception of unencrypted voice traffic.
- **AitM:** Interception or manipulation of communications.
- **DoS:** Disruption of VoIP services.
- **VLAN Hopping:** Unauthorized movement between network segments.

### 7.3  Software-Defined Networking (SDN)

- **SDN:** Separates network control from packet forwarding, enabling centralized and programmable network management.

- **Control Plane:** Decides where network traffic should go.
- **Data Plane:** Forwards packets according to the configured rules.
- **SDN Controller:** Centrally manages network devices and policies.

**SDN Interfaces:**
- **Northbound:** Controller ↔ Applications.
- **Southbound:** Controller ↔ Network Devices.
- **Eastbound/Westbound:** Communication between peer components.

### 7.4 Related Technologies

- **NFV (Network Functions Virtualization):** Runs network functions as software instead of dedicated hardware.
- **VSAN (Virtual SAN):** Software-based virtualized shared storage.
- **SDS (Software-Defined Storage):** Policy-driven storage management independent of underlying hardware.
- **SD-WAN:** Centrally manages WAN connectivity between branches, data centers and cloud services.


## 8. Wireless. 

### 8.1  Wi-Fi Modes and Access Points. 

### 8.2  Wi-Fi Operating Modes.  

- **Ad Hoc Mode (Peer-to-Peer):** Devices communicate directly without a Wireless Access Point (WAP).
- **Wi-Fi Direct:** Enhanced peer-to-peer Wi-Fi supporting WPA2/WPA3.
- **Infrastructure Mode:** Devices connect through a WAP, which manages wireless access.

### 8.3  Infrastructure Mode Types. 

- **Stand-alone:** WAP connects wireless devices only; no wired network connection.
- **Wired Extension:** WAP connects wireless devices to a wired network.
- **Enterprise Extended:** Multiple WAPs use the same ESSID, allowing devices to roam between WAPs.
- **Bridge Mode:** Wireless connection links two wired networks (e.g., between buildings).

### 8.4 Wireless Access Point Types. 

- **Fat AP:** Stand-alone access point; manages configuration and security locally.
- **Thin AP:** Centrally managed by a wireless controller; primarily handles wireless transmission.
- **Wireless Controller:** Centralizes AP configuration, security and management.

### 8.5 Wi-Fi Identifiers and Security

- **SSID:** Name of a Wi-Fi network.
- **ESSID:** Network name shared by multiple WAPs, supporting roaming.
- **ISSID:** Identifier used in ad hoc / Wi-Fi Direct networks.
- **BSSID:** MAC address identifying a specific WAP (or initiating device).
- **Beacon Frame:** WAP broadcasts the SSID to announce the wireless network.
- **SSID Hiding:** Disabling SSID broadcast does not provide real security; attackers can still discover it.
- **Best Practice:** Change default SSID and use WPA2/WPA3 for authentication and encryption.

### 8.6 Authentication and Encryption. 

- **Wi-Fi Encryption:** Protects communication only between the client and WAP; use VPN or TLS for end-to-end encryption.
- **OSA (Open System Authentication):** No real authentication required; typically communicates in cleartext.
- **SKA (Shared Key Authentication):** Requires authentication using a shared key.

### 8.7 WEP (Wired Equivalent Privacy).  

- **WEP:** Original IEEE 802.11 wireless security protocol.
- **Encryption:** Uses RC4 with a static shared key.
- **Weakness:** Easily cracked due to cryptographic flaws.
- **Recommendation:** Avoid WEP; use WPA2 or WPA3 instead.


### 8.8 Wi-Fi Security Protocols

- **WPA (Wi-Fi Protected Access):** Replaced WEP; uses RC4 with TKIP and dynamic keys. Now insecure.
- **TKIP:** Temporary security improvement introduced with WPA; now deprecated.
- **WPA2 (802.11i):** Replaced WPA; uses AES-CCMP for encryption and data integrity.
  - **KRACK:** Attack targeting WPA2 key exchange.
- **WPA3:** Improved wireless security using SAE authentication and management frame protection.
  - **WPA3-Personal:** Uses SAE instead of traditional PSK authentication. (SAE - Simulataneous authentication of equals)
  - **WPA3-Enterprise:** Supports stronger 192-bit security mode.

### 8.9 Wi-Fi Authentication

- **PSK (Pre-Shared Key):** Uses a shared password for wireless authentication.
- **802.1X:** Port-based network access control using centralized authentication.
- **EAP:** Authentication framework supporting different authentication methods.
- **SAE (Simultaneous Authentication of Equals):** WPA3 password-based authentication using Dragonfly Key Exchange.
- **RADIUS:** Centralized AAA service; UDP 1812 (authentication), 1813 (accounting).
- **TACACS+:** Centralized AAA service; TCP 49.

### 8.10 EAP Methods

- **LEAP:** Cisco proprietary authentication method; insecure and vulnerable to password attacks.
- **PEAP:** Protects EAP authentication inside a TLS tunnel.
- **EAP-TLS:** Certificate-based authentication; recommended over LEAP.

### 8.11 Wi-Fi Protected Setup (WPS)

- **WPS:** Simplifies connecting new devices using a button or PIN.
- **Risk:** PIN-based WPS is vulnerable to brute-force attacks.
- **Best Practice:** Disable WPS to reduce unauthorized access risk.


### 8.12 Wireless Security and Communication Technologies

### 8.13 Wireless MAC Filtering

- **MAC Filtering:** Allows only approved MAC addresses to connect to a WAP.
- **Weakness:** MAC addresses can be sniffed and spoofed, so MAC filtering is not a reliable security control.

### 8.14 Wireless Antennas

- **Omnidirectional Antenna:** Transmits signals in multiple directions; commonly used in WAPs.
- **Directional Antenna:** Focuses signals in a specific direction.
  - Examples: Yagi, Cantenna, Panel, Parabolic.
- **Antenna Placement:** Avoid physical obstructions, metal surfaces, and electrical interference.

### 8.15 Captive Portal

- **Captive Portal:** Redirects users to a web page for authentication, payment, or acceptance of usage policies.
- **Use Cases:** Public Wi-Fi at hotels, airports, libraries, etc.

### 8.16 Wi-Fi Security Best Practices

- Update WAP firmware and change default administrator passwords.
- Use WPA2/WPA3 with strong authentication.
- Disable unnecessary features and change default SSID.
- **Network Segmentation:** Separate wireless networks from sensitive wired networks using firewalls.
- **WIDS (Wireless Intrusion Detection System):** Detects suspicious wireless activities.
- **WIPS (Wireless Intrusion Prevention System):** Detects and blocks wireless threats.
- Use VPN when additional communication protection is required.
- Monitor and log wireless activities.

### 8.17 Wireless Communication Technologies

- **Spread Spectrum:** Uses multiple frequencies to transmit data.
- **FHSS (Frequency Hopping Spread Spectrum):** Rapidly switches between frequencies during transmission.
- **DSSS (Direct Sequence Spread Spectrum):** Spreads signals across frequencies using chipping codes.
- **OFDM (Orthogonal Frequency-Division Multiplexing):** Uses multiple orthogonal subcarriers to improve data throughput.
- **MIMO (Multiple Input, Multiple Output):** Uses multiple antennas to improve speed and reliability.
- **TDMA (Time Division Multiple Access):** Multiple users share a frequency using different time slots.
- **CDMA (Code Division Multiple Access):** Multiple users share the same frequency using unique codes.


### 8.18 Bluetooth Vulnerabilities

- **Bluesniffing:** Capturing Bluetooth network traffic.
- **Bluesmacking:** DoS attack that disrupts Bluetooth communication.
- **Bluejacking:** Sending unsolicited Bluetooth messages.
- **Bluesnarfing:** Unauthorized access to or theft of data from a Bluetooth device.
- **Bluebugging:** Gaining remote control of a Bluetooth device (e.g., activating its microphone).
- **BLUFFS:** Attacks Bluetooth session security, potentially exposing past and future communications.


### 8.19 RFID, NFC and Wireless Attacks

- **RFID (Radio Frequency Identification):** Uses radio signals to identify and track objects through RFID tags.
  - **Risk:** Unauthorized scanning and tracking of tags.

- **NFC (Near-Field Communication):** Short-range wireless communication (typically within 4 cm).
  - **Uses:** Contactless payments, device pairing, data exchange.
  - **Risks:** Eavesdropping, replay attacks, AitM, data manipulation.

### 8.20 Wireless Attacks

- **War Driving:** Searching for wireless networks using Wi-Fi scanning tools.
  - **War Flying:** Same technique using drones.

- **Rogue Access Point:** Unauthorized WAP connected to or impersonating a legitimate network.
  - **Defense:** WIDS to detect unauthorized access points.

- **Evil Twin:** Fake WAP impersonating a legitimate WAP to trick users into connecting.
  - **Risks:** Eavesdropping, credential theft, AitM attacks.

- **Disassociation Attack:** Maliciously disconnects wireless clients using forged disassociation frames.
  - **Risk:** DoS or forcing clients to reconnect to a malicious WAP.

- **Deauthentication Attack:** Uses forged deauthentication frames to disconnect authenticated clients.
  - **Risk:** DoS and disruption of wireless sessions.

- **Jamming:** Deliberately interferes with wireless radio signals.
  - **Risk:** Denial of Service (DoS).

- **IV Abuse:** Exploits weak, reused, or improperly generated initialization vectors.
  - **Example:** WEP encryption attacks.

- **Replay Attack:** Captures valid communication and retransmits it to gain unauthorized access.
  - **Defense:** Timestamps, nonces, challenge-response authentication.

### 8.21 Wireless Security Best Practices

- **WIDS:** Detects rogue WAPs and suspicious wireless activity.
- **WPA3:** Improves wireless security and protects management frames.
- **VPN:** Protects communications over untrusted wireless networks.
- **Firmware Updates:** Fix known wireless vulnerabilities.
- **Disable Auto-Connect:** Remove unnecessary saved Wi-Fi networks.

## 9. Communiations


### 9.1 Satellite Communications

- **LEO (Low Earth Orbit):** Low altitude, lower latency, smaller coverage area; requires multiple satellites.
- **MEO (Medium Earth Orbit):** Higher altitude than LEO, larger coverage, increased latency.
- **GEO (Geostationary Orbit):** Appears stationary above Earth; large coverage, highest latency; supports fixed ground antennas.

### 9.2 Cellular Networks

- **4G (LTE):** IP-based voice and data communications.
- **5G:** Higher speeds and lower latency; higher-frequency signals can have shorter range.
- **Security Risks:** Eavesdropping, fake cell towers, AitM attacks, and insecure access to corporate networks.
- **Protection:** Use TLS or VPN for sensitive communications.

### 9.3 Content Delivery Networks (CDN)

- **CDN:** Distributes content across geographically dispersed servers closer to users.
  - **Benefits:** Lower latency, improved performance, availability, and load distribution.
- **SDP (Service Delivery Platform):** Architecture for delivering services such as VoIP, SaaS, and online gaming.

### 9.4 Secure Network Segments

- **Intranet:** Private network accessible to internal users.
- **Extranet:** Private network resources shared with authorized external users (partners, suppliers, customers).
- **Screened Subnet (DMZ):** Isolated network for publicly accessible services, separated from the internal network by firewalls.
- **Screened Host:** Firewall-protected intermediary that filters inbound traffic and protects internal systems.

### 9.5 Network Traffic Directions

- **East-West:** Traffic between systems within a network or data center.
- **North-South:** Traffic entering or leaving a network.

### 9.6 Network Equipment

- **Repeater / Hub (Layer 1):** Regenerates signals; does not separate collision or broadcast domains.
- **Bridge (Layer 2):** Connects network segments using MAC addresses.
- **Switch (Layer 2):** Forwards frames using MAC addresses; separates collision domains.
- **Router (Layer 3):** Routes packets using IP addresses; separates broadcast domains.
- **Layer 3 Switch:** Combines switching and routing functionality.
- **MPLS:** Forwards traffic using labels instead of traditional IP lookup.
- **Multiplexer (MUX):** Combines multiple signals for transmission over a shared medium.

#### 9.7 Collision vs. Broadcast Domains

- **Collision Domain:** Network segment where simultaneous transmissions can collide.
  - Separated by switches (Layer 2).
- **Broadcast Domain:** Devices that receive the same broadcast traffic.
  - Separated by routers (Layer 3) or VLAN boundaries.

### 9.8 Other Network Components

- **Jump Server / Jumpbox:** Hardened intermediary for securely accessing restricted systems or networks.
- **Bastion Host:** Hardened system exposed to potential attacks, such as a firewall or jump server.
- **Sensor:** Detects and collects events or network information.
- **Collector:** Gathers and records logs or events.
- **Aggregator:** Combines information from multiple sources for centralized processing.
- **SoC (System on a Chip):** Integrates computing components into one chip; limited security capabilities may create risks.

### 9.9 Network Access Control (NAC)

- **NAC:** Enforces network access policies based on device identity, security configuration, and compliance.

- **Preadmission NAC:** Checks device security compliance before granting network access.
- **Postadmission NAC:** Monitors activity and enforces access restrictions after connection.

- **Agent-Based NAC:** Uses installed software to check device compliance.
- **Agentless NAC:** Assesses devices remotely through network monitoring and scanning.
- **Quarantine / Remediation:** Isolates noncompliant devices until security requirements are met.
- **802.1X:** Port-based network authentication; can be part of a NAC solution.

### 9.10 Firewalls

- **Firewall:** Filters network traffic based on security rules between different trust zones.
- **Implicit Deny:** Blocks traffic unless explicitly allowed.
- **Ingress Filtering:** Filters incoming traffic.
- **Egress Filtering:** Filters outgoing traffic.
- **Bastion Host:** Hardened system designed to withstand attacks.

### 9.11 Firewall Types

- **Packet-Filtering (Stateless):** Evaluates each packet independently using IP addresses, ports, and ACLs.
- **Stateful Inspection:** Tracks connection states and previous packets to make filtering decisions.
- **Circuit-Level Firewall:** Controls the establishment of communication sessions (e.g., SOCKS).
- **Application-Level Firewall:** Filters traffic based on application protocols and content (Layer 7).
- **WAF (Web Application Firewall):** Protects web applications against application-layer attacks.
- **NGFW (Next-Generation Firewall):** Combines traditional firewall functions with DPI, application filtering, IDS/IPS, and other security controls.
- **Host-Based Firewall:** Protects an individual computer or server.
- **ISFW (Internal Segmentation Firewall):** Controls traffic between internal network segments to reduce lateral movement.

### 9.12 Related Firewall Concepts

- **DPI (Deep Packet Inspection):** Examines packet payloads, not just headers.
- **UTM (Unified Threat Management):** Combines multiple security functions in one solution.
- **RTBH (Remotely Triggered Black Hole):** Drops unwanted network traffic before it reaches its destination.
- **Firewall Limitation:** Only protects traffic passing through it; misconfiguration or failure can create security gaps.

### 9.13 Proxy Servers

- **Proxy:** Intermediary between clients and servers; can provide filtering, caching, and identity protection.
- **Forward Proxy:** Handles requests from internal clients to external services.
- **Reverse Proxy:** Handles incoming requests from external clients to internal servers.
- **Transparent Proxy:** Intercepts traffic without requiring explicit client proxy configuration.
- **Nontransparent Proxy:** Client is explicitly configured to use the proxy.

### 9.14 Content Filtering

- **URL Filtering:** Blocks access based on website addresses or URL patterns.
- **Content Filtering:** Inspects application payloads for unwanted content.
- **Secure Web Gateway (SWG):** Provides web filtering, malware protection, and other web security controls.

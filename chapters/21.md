
# CISSP Chapter 21 — Malicious Code and Application Attacks

**Domains:** 3 — Security Architecture and Engineering, 7 — Security Operations, 8 — Software Development Security

## 1. Malware Types

| Type | CISSP Key Point |
|---|---|
| Virus | Attaches to host file/boot area; requires execution to propagate |
| Worm | Self-replicates and spreads without user intervention |
| Trojan | Appears legitimate but contains malicious functionality |
| Logic Bomb | Activates when a specified condition/time occurs |
| RAT | Remote Access Trojan; provides unauthorized remote control |
| Spyware | Secretly monitors activity and collects information |
| Adware | Displays unwanted advertisements |
| Ransomware | Encrypts data and demands ransom; may threaten data disclosure |
| Fileless Malware | Executes primarily in memory, often using scripts |
| Rootkit | Conceals malicious activity and may maintain privileged access |
| Cryptomalware | Uses infected systems for unauthorized cryptocurrency mining |

## 2. Virus Propagation and Evasion

| Type | Characteristic |
|---|---|
| MBR/Boot Sector | Infects system boot components |
| File Infector | Infects executable files |
| Companion | Uses a similar filename to run instead of legitimate software |
| Macro | Infects documents through application macros |
| Service Injection | Injects malware into trusted OS processes |
| Multipartite | Uses multiple infection techniques |
| Stealth | Hides infection by manipulating system behavior |
| Polymorphic | Changes code/signature between infections |
| Encrypted | Encrypts viral code and uses a decryption routine |

## 3. Malware Detection and Protection

- **Signature-Based:** Identifies known malware; depends on updated signatures.
- **Heuristic/Behavioral:** Identifies suspicious behavior, including previously unknown malware.
- **Sandbox:** Executes suspicious files in an isolated environment.
- **File Integrity Monitoring (FIM):** Detects unauthorized file changes using hashes.
- **EDR:** Endpoint monitoring, threat detection, isolation, and response.
- **MDR:** Managed detection and response service.
- **UEBA:** Detects abnormal user/entity behavior by comparing activity against behavioral baselines.
- **Zero-Day:** Exploitation of a vulnerability before an effective fix is available.
- **Window of Vulnerability:** Period during which a vulnerability remains exploitable.

## 4. Application and Memory Attacks

| Attack | Description |
|---|---|
| Buffer Overflow | Input exceeds allocated memory boundaries |
| Integer Overflow | Numeric result exceeds permitted integer range |
| TOCTTOU | Race condition between checking and using a resource |
| Backdoor | Undocumented mechanism bypassing normal access controls |
| Privilege Escalation | Obtaining higher privileges than originally authorized |
| Memory Leak | Memory not released, resulting in resource exhaustion |
| Null Pointer Dereference | Accessing memory through a NULL pointer; may cause failure |

## 5. Injection Attacks

- **SQL Injection:** Injects SQL statements to read, modify, or delete database information.
- **Blind Content-Based SQLi:** Infers query results through differences in application responses.
- **Blind Timing-Based SQLi:** Infers information through response delays.
- **Command Injection:** Executes unauthorized operating-system commands.
- **LDAP Injection:** Manipulates directory service queries.
- **XML Injection:** Manipulates XML processing.
- **Code Injection:** Causes execution of attacker-supplied code.
- **DLL Injection:** Loads malicious code through dynamic libraries.

**Primary SQLi Defense:** Parameterized queries/prepared statements. Properly implemented stored procedures can also help prevent injection.

## 6. Web Application Attacks

| Attack | Key Distinction |
|---|---|
| IDOR | Changes object identifiers to access unauthorized resources |
| Directory Traversal | Uses paths such as `../` to reach restricted files |
| Local File Inclusion (LFI) | Includes files from the local server |
| Remote File Inclusion (RFI) | Includes attacker-controlled files from remote locations |
| Reflected XSS | Malicious script immediately reflected in a response |
| Stored XSS | Malicious script stored and delivered to future visitors |
| DOM-Based XSS | Unsafe client-side DOM manipulation executes malicious script |
| CSRF/XSRF | Tricks authenticated user's browser into unauthorized requests |
| SSRF | Tricks a server into requesting attacker-selected URLs |
| Session Hijacking | Takes over an established authenticated session |
| Web Shell | Enables remote command execution through web requests |

### Critical Distinctions

- **XSS:** Executes attacker-controlled script in the victim's browser.
- **CSRF:** Performs unauthorized actions through the victim's authenticated session.
- **SSRF:** Causes the server to make attacker-directed requests.
- **IDOR:** Missing object-level authorization.
- **Directory Traversal:** Unauthorized file access through path manipulation.
- **File Inclusion:** Application includes attacker-selected files, potentially executing code.

## 7. Application Security Countermeasures

| Control | Primary Purpose |
|---|---|
| Server-Side Input Validation | Reject invalid/malicious input |
| Allowlisting | Accept only explicitly permitted input |
| Output Encoding | Prevent untrusted content from executing as browser code |
| Parameterized Queries | Prevent SQL injection |
| Anti-CSRF Tokens | Prevent unauthorized cross-site requests |
| Object-Level Authorization | Prevent IDOR |
| WAF | Filter malicious web requests at Layer 7 |
| Secure Session Management | Prevent session compromise and reuse |
| Code Signing | Verify software publisher authenticity and integrity |
| Code Integrity Hashing | Detect code modifications |

### Additional CISSP Distinctions

- **Parameter Pollution:** Multiple values for the same parameter may exploit inconsistent validation.
- **Hard-Coded Credentials:** Expose secrets and may introduce backdoors.
- **Code Signing:** Does not guarantee software is malware-free.
- **Data Minimization:** Avoid collecting or retaining unnecessary sensitive information.
- **Tokenization:** Replaces sensitive data with tokens using a protected mapping.
- **Salting:** Adds random data before password hashing to resist precomputed attacks.
- **Elasticity:** Automatically adjusts resources with changing demand, unlike scalability alone.

# Chapter 12 — Secure Communications and Network Attacks

**Exam:** ISC2 CISSP  
**Domain:** Communication and Network Security (Domain 4)  
**Study Guide:** ISC2 CISSP Official Study Guide, 10th Edition

> **Study approach:** Understand what each technology does, what security property it provides, what it does NOT provide, and how to identify it in a scenario.

## 1. Secure Communication Principles and Transparency

- **Security Control Transparency:** A security control operates without unnecessary user interaction or disruption. It is not the same as invisibility to attackers or security through obscurity.
- **Confidentiality:** Prevents unauthorized disclosure of information through encryption and access controls.
- **Integrity:** Detects unauthorized modification using cryptographic MACs, HMACs, or digital signatures.
- **Authentication:** Verifies the identity of communicating users or systems.
- **Availability:** Ensures network resources remain accessible through redundancy, QoS, and fault tolerance.
- **Nonrepudiation:** Provides evidence that a sender performed an action or transmitted a message, typically using digital signatures.
- **Security Design:** Select controls based on identified threats, asset value, and business requirements.

**Exam distinction:** A security mechanism that operates unnoticed by legitimate users is called **transparency**, not invisibility.

## 2. Protocol Security, Authentication, and Network Access

### 2.1 PPP Authentication

- **PPP (Point-to-Point Protocol):** OSI Layer 2 protocol that supports point-to-point connections and authentication.
- **PAP (Password Authentication Protocol):**
  - Sends usernames and passwords without encryption by PAP itself.
  - Vulnerable to credential interception.
  - Does not protect logon credentials.
- **CHAP (Challenge Handshake Authentication Protocol):**
  - Uses challenge-response authentication.
  - Avoids transmitting the password directly.
  - Supports periodic reauthentication.
  - Legacy implementation with known weaknesses.
- **EAP (Extensible Authentication Protocol):**
  - Authentication framework supporting multiple authentication methods.
  - Security depends on the selected EAP method.
- **RADIUS:**
  - Centralized AAA service.
  - Commonly used with EAP and IEEE 802.1X.
  - Traditionally uses UDP 1812 for authentication and 1813 for accounting.

| Protocol | Authentication Mechanism | Security |
|---|---|---|
| PAP | Plaintext credentials | Insecure |
| CHAP | Challenge-response | Better than PAP, but legacy |
| EAP | Extensible framework | Depends on method |
| 802.1X | Port-based network access | Depends on EAP method |

### 2.2 EAP Authentication Methods

- **LEAP:** Cisco Lightweight EAP; legacy and vulnerable to password attacks.
- **PEAP:** Protected EAP; uses a TLS tunnel to protect inner authentication.
- **EAP-TLS:** Uses TLS and client/server certificates for mutual authentication.
- **EAP-TTLS:** Establishes a TLS tunnel before client authentication, often protecting password-based credentials.
- **EAP-SIM:** Uses SIM credentials for authentication.
- **EAP-FAST:** Cisco Flexible Authentication via Secure Tunneling; developed to improve upon LEAP.
- **EAP-MD5:** Legacy MD5-based challenge authentication; insecure for modern enterprise wireless use.
- **EAP-POTP:** Uses protected one-time passwords.
- **EAP-IKEv2:** Uses IKEv2-based authentication mechanisms.
- **EAP-NOOB:** Uses out-of-band onboarding methods such as QR codes or NFC.

**Exam distinction:**

Valid methods include LEAP, PEAP, EAP-SIM, EAP-FAST, EAP-MD5, EAP-POTP, EAP-TLS, and EAP-TTLS.

EAP-VPN, EAP-MBL, and VEAP are not recognized methods in the study guide's review question.

### 2.3 IEEE 802.1X and NAC

- **802.1X:** Port-based network access control for wired and wireless networks.
- **Supplicant:** Endpoint requesting network access.
- **Authenticator:** Switch or wireless access point controlling network admission.
- **Authentication Server:** Usually RADIUS/AAA server verifying credentials.
- **NAC (Network Access Control):**
  - Verifies device identity and security compliance.
  - Can allow, restrict, or quarantine endpoints.
  - May evaluate patches, antivirus/EDR status, and security configurations.
- **Security Controls:** Strong EAP methods, certificate validation, endpoint posture checking, reauthentication, and monitoring.

**Important:** 802.1X provides access control, not automatic encryption of all network traffic.

### 2.4 Port Security

Port security can refer to different security layers.

- **Physical Port Security (Layer 1):**
  - RJ-45 wall outlets and switch ports.
  - Secure patch panels and wiring closets.
  - Disable unused physical network ports.
- **Logical Port Security (Layer 2):**
  - IEEE 802.1X.
  - NAC.
  - MAC address restrictions.
  - Switch port security.
- **Transport-Layer Port Security (Layer 4):**
  - TCP/UDP service ports.
  - Close unnecessary ports.
  - Apply firewall rules and service restrictions.

**Exam distinction:** Port security includes physical RJ-45 connections, NAC, and Transport Layer controls.

## 3. Network Quality, Performance, and Availability

### 3.1 Quality of Service (QoS)

- **QoS:** Manages and prioritizes network communications to preserve performance and availability.
- **Bandwidth:** Maximum available communication capacity.
- **Bit Rate:** Number of bits transmitted per second.
- **Throughput:** Actual successful data transmission rate.
- **Goodput:** Useful application payload delivered, excluding overhead and retransmissions.
- **Latency:** Time required for data to travel between endpoints.
- **Jitter:** Variation in packet arrival delay.
- **Packet Loss:** Packets dropped or lost during transmission.
- **Interference:** Electromagnetic or radio interference that disrupts communication.
- **SNR (Signal-to-Noise Ratio):** Ratio between usable signal and background noise; higher is generally better.
- **Availability:** Percentage of time a network service remains operational.

### 3.2 Network Performance Controls

- **Traffic Shaping:** Controls traffic flow to reduce congestion.
- **Traffic Policing:** Restricts or drops traffic exceeding configured limits.
- **Traffic Prioritization:** Gives critical traffic higher priority.
- **Capacity Management:** Predicts network resource requirements and prevents congestion.
- **Fault Management:** Detects failures and restores service.
- **Network Observability:** Uses logs, metrics, and traces to identify network issues.

**Exam scenario:** If users experience interrupted connections, dropped data, or poor VoIP quality, evaluate bandwidth, throughput, latency, jitter, packet loss, interference, and SNR.

**Security relevance:** QoS primarily supports **Availability** in the CIA triad.

## 4. Secure Voice Communications

### 4.1 Voice Technologies

- **PSTN (Public Switched Telephone Network):** Traditional telecommunications infrastructure.
- **PBX (Private Branch Exchange):** Organizational telephone switching system managing internal extensions and external calls.
- **VoIP (Voice over IP):** Transmits voice communications across IP networks.
- **SIP (Session Initiation Protocol):** Common VoIP signaling protocol.
- **SRTP (Secure Real-Time Transport Protocol):** Provides encryption and integrity protection for voice/video media.

### 4.2 Voice Communication Threats

- **Phreaking:** Unauthorized exploitation of telephone systems or carrier services.
- **PBX Toll Fraud:** Unauthorized use of PBX facilities for billable or restricted calls.
- **Vishing:** Voice-based phishing or social engineering.
- **Caller ID Spoofing:** Forging the displayed caller identity.
- **VoIP Eavesdropping:** Unauthorized interception of voice communications.
- **VoIP Session Hijacking:** Unauthorized takeover of communication sessions.
- **VoIP DoS:** Disrupting voice services by overwhelming resources.

### 4.3 PBX Security Controls

- **Change default passwords:** Important preventive protection against PBX compromise.
- Disable unused PBX features and remote access services.
- Restrict international and premium-rate dialing.
- Implement strong authentication for administrative access.
- Monitor call logs for unusual activity.
- Patch PBX systems and secure physical infrastructure.
- **DISA (Direct Inward System Access):** Allows remote access to PBX services; requires strong authentication and restrictions.
- **Callback Verification:** Confirm suspicious telephone requests using a previously trusted number.

**Exam distinction:**

- Phreaking targets telephone systems, particularly PBX services.
- Changing default PBX passwords is preventive.
- Reviewing telephone logs is primarily detective.
- VoIP encryption may terminate at gateways; it is not necessarily end-to-end.

## 5. Remote Access and Administration

### 5.1 Remote Access Types

- **Service-Specific Access:** Provides remote access to a specific service, such as email.
- **Remote-Control Access:** Allows users to control a computer located elsewhere.
- **Remote-Node Access:** Connects a remote endpoint logically to an internal network, commonly using VPN.
- **Remote Administration:** Privileged remote management of systems, network devices, accounts, and security configurations.

### 5.2 Remote Access Security Controls

- **MFA:** Protect authentication against credential compromise.
- **Least Privilege:** Restrict access to required resources.
- **RBAC:** Assign permissions based on organizational roles.
- **Encrypted Connections:** Use VPN, TLS, or SSH.
- **Endpoint Compliance:** Verify patches, endpoint protection, and configurations.
- **NAC:** Validate devices before network admission.
- **Managed Devices:** Prefer company-controlled endpoints.
- **Jump Hosts/Bastion Hosts:** Restrict administrative access to controlled entry points.
- **Access Logging:** Monitor remote sessions and unusual behavior.
- **Remote Access Policy:** Define permitted users, devices, protocols, activities, and security requirements.

### 5.3 Remote Access Risks

- Lost or stolen devices.
- Malware on unmanaged endpoints.
- Insecure home or public networks.
- Unauthorized secondary connections.
- Compromised credentials.
- Inadequate endpoint patching.
- Split-tunnel exposure.

**Exam principle:** Prefer restricted, authenticated access to specific business resources rather than unnecessary full network access.

## 6. Multimedia Collaboration and Instant Messaging

- **Multimedia Collaboration:** Remote meetings, video conferencing, instant messaging, file sharing, and collaborative documents.

### Security Controls

- **Encryption:** Protect communications against disclosure.
- **MFA:** Prevent unauthorized account access.
- **Access Control:** Restrict meeting participation and shared resources.
- **Logging and Auditing:** Maintain records of security-relevant activity.
- **Malware Protection:** Scan shared files and attachments.
- **Recording Controls:** Restrict recording, storage, sharing, and retention.
- **Centralized Management:** Enforce organizational security policies.

### Security Threats

- Unauthorized meeting participants.
- Impersonation and social engineering.
- Malware through attachments.
- Unauthorized recordings.
- Confidential information disclosure.
- Insecure third-party platforms.

**Exam distinction:** Encryption, MFA, and logging are security controls. Avatar customization and video filters are not security mechanisms.

## 7. Monitoring, Load Balancing, and Resilience

### 7.1 Network Monitoring

- **Network Observability:** Uses metrics, logs, flow records, and traces to evaluate network behavior.
- **Capacity Management:** Ensures adequate resources for current and future demand.
- **Fault Management:** Detects network failures and supports recovery.

### 7.2 Load Balancing

- **Load Balancing:** Distributes requests across multiple systems to improve performance and availability.
- **Round Robin:** Distributes requests sequentially.
- **Weighted Distribution:** Allocates requests according to server capacity or priority.
- **Least Connections:** Selects the server with the fewest active connections.
- **Session Affinity:** Sends requests from the same client to the same backend server.
- **VIP (Virtual IP):** Single logical IP representing multiple backend servers.
- **GSLB (Global Server Load Balancing):** Distributes traffic across geographically separated data centers.
- **TLS Offloading:** Load balancer performs TLS processing instead of backend servers.

### 7.3 High Availability

- **Active-Active:** Multiple servers handle traffic simultaneously.
- **Active-Passive:** Standby server takes over following primary failure.
- **Failover:** Transfers operations to another system when the primary fails.
- **Common-Mode Failure:** Shared infrastructure can cause multiple redundant systems to fail together.

**Exam distinction:** Redundancy is effective only when redundant components do not share critical single points of failure.

## 8. Email Security, Retention, and Nonrepudiation

### 8.1 Email Protocols

| Protocol | Function | Ports |
|---|---|---|
| SMTP | Sending and relaying email | TCP 25 |
| SMTP Submission | Authenticated mail submission | TCP 587 |
| SMTPS | Implicit TLS submission | TCP 465 |
| POP3 | Retrieving email | TCP 110 |
| POP3S | POP3 over TLS | TCP 995 |
| IMAP | Accessing server-stored email | TCP 143 |
| IMAPS | IMAP over TLS | TCP 993 |

- **STARTTLS:** Upgrades an existing plaintext protocol connection to TLS.
- **SMTP:** Primarily sends and relays email.
- **POP3:** Primarily retrieves/downloads email.
- **IMAP:** Supports accessing and managing server-stored messages.

### 8.2 Email Security Threats

- **Open Relay:** Mail server improperly allows unauthorized third-party message relaying.
- **Email Spoofing:** Falsified sender identity.
- **Mail Bombing:** Deliberate email flooding intended to cause disruption.
- **Mail Storm:** Excessive message generation through reply-all or automatic responses.
- **Phishing:** Deceptive messages intended to obtain sensitive information.
- **Malicious Attachments:** Files containing malware or harmful scripts.

### 8.3 Email Security Controls

- **S/MIME:**
  - Uses public-key cryptography and X.509 certificates.
  - Supports encryption and digital signatures.
  - Provides confidentiality, integrity, sender authentication, and evidence supporting nonrepudiation.
- **PGP/OpenPGP:**
  - Supports public-key encryption and digital signatures.
  - Uses a different key-trust model from traditional X.509 PKI.
- **SPF (Sender Policy Framework):**
  - Defines authorized sending servers for a domain.
  - Helps detect unauthorized use of domain identities.
- **DKIM (DomainKeys Identified Mail):**
  - Uses cryptographic signatures to authenticate a signing domain and detect message alteration.
- **DMARC:**
  - Uses SPF/DKIM alignment with the visible From domain.
  - Defines policies such as none, quarantine, and reject.
- **Encryption:** Provides confidentiality.
- **Digital Signatures:** Provide integrity, authentication, and evidence supporting nonrepudiation.
- **Filtering:** Detects spam, phishing, malicious attachments, and suspicious links.

### 8.4 Email Retention Policy

- **Retention Period:** Specifies how long email records must be preserved.
- **Privacy:** Defines employee privacy expectations and monitoring.
- **Auditor Review:** Identifies circumstances where authorized auditors can access email.
- **Legal Hold:** Suspends deletion when relevant information must be preserved.
- **Archive:** Long-term storage intended for records preservation and retrieval.
- **Backup:** Recovery mechanism following data loss or system failure.
- **Secure Disposal:** Authorized destruction after retention requirements expire.

**Important distinctions:**

- Backups are not necessarily compliant archives.
- Retention policies should explain duration, privacy, and authorized access.
- Technical backup methods generally do not need to be communicated to end users.
- Data-remanence destruction is less directly related to securing email transmission than integrity, access control, and nonrepudiation.

## 9. VPNs, Tunneling, and IPSec

### 9.1 Virtual Private Networks

- **VPN (Virtual Private Network):** Establishes a logical communication path over an existing intermediary network.
- **Site-to-Site VPN:** Connects separate organizational networks.
- **Remote-Access VPN:** Connects remote users to organizational resources.
- **Host-to-Host VPN:** Protects communication between individual endpoints.
- **VPN Concentrator:** Manages multiple VPN connections.

**VPN Requirements:**

- An underlying network connection must already exist.
- VPNs can provide confidentiality, integrity, and authentication when appropriately configured.
- VPNs cannot create a missing physical network path.
- VPNs do not guarantee availability.

**Exam scenario:** Two systems without any intermediary network connectivity cannot establish communication using a VPN.

### 9.2 Tunneling

- **Tunneling:** Encapsulates packets from one protocol inside another.
- **Security Limitation:** Tunneling alone does not provide encryption.
- **Risk:** Encapsulated traffic may bypass security filters if they inspect only the outer protocol.

### 9.3 VPN Traffic Routing

- **Split Tunnel:**
  - Corporate traffic travels through VPN.
  - Other Internet traffic travels directly.
  - Risk: Bypasses organizational traffic inspection and security controls.
- **Full Tunnel:**
  - All endpoint traffic passes through VPN.
  - Supports centralized security enforcement.
- **Always-On VPN:** Automatically establishes protected connectivity according to policy.

### 9.4 IPSec Modes

| Mode | Protection | Typical Use |
|---|---|---|
| Transport | Protects payload; original IP header remains visible | Host-to-host |
| Tunnel | Protects entire original IP packet when ESP encryption is used; adds new outer IP header | Site-to-site VPN |

- **Transport Mode:** Retains the original IP header.
- **Tunnel Mode:** Encapsulates the original packet within a new IP packet.
- **Tunnel Mode + ESP:** Encrypts the original IP packet, including its header.
- **Outer IP Header:** Remains visible to support routing.
- **AH Tunnel Mode:** Provides integrity/authentication but does not encrypt.

**Exam distinction:** For encryption of the original IP header and payload, select **IPSec Tunnel Mode with ESP**.

### 9.5 IPSec Components

- **AH (Authentication Header):**
  - Data-origin authentication.
  - Message integrity.
  - Anti-replay protection.
  - Does NOT provide confidentiality.

- **ESP (Encapsulating Security Payload):**
  - Provides encryption/confidentiality when encryption is enabled.
  - Can provide integrity and authentication.
  - Supports anti-replay protection.

- **IKE (Internet Key Exchange):**
  - Negotiates cryptographic parameters.
  - Establishes keys and security associations.

- **SA (Security Association):**
  - Contains negotiated security parameters.
  - Unidirectional; bidirectional IPSec communication requires SAs for both directions.

- **HMAC:** Provides keyed message integrity and authentication.
- **Anti-Replay Protection:** Uses sequence numbers and replay-window processing.
- **NAT-T (NAT Traversal):** Allows IPSec traffic through NAT devices, commonly using UDP 4500.

### 9.6 Other VPN and Tunneling Protocols

- **PPTP:** Legacy insecure tunneling protocol.
- **L2TP:** Layer 2 tunneling without native encryption; commonly paired with IPSec.
- **GRE:** Encapsulation without inherent encryption.
- **SSH:** Secure encrypted administration and tunneling; TCP 22.
- **OpenVPN:** TLS-based VPN technology.

**Exam priority:**

- AH = Integrity + Authentication.
- ESP = Encryption + Optional Integrity/Authentication.
- IKE = Key Negotiation.
- Tunnel Mode = Protects original IP packet.
- Transport Mode = Original IP header remains.

## 10. Switching, VLANs, and Layer 2 Threats

### 10.1 Ethernet Switching

- **Switch:** Primarily OSI Layer 2 device forwarding Ethernet frames using destination MAC addresses.
- **CAM/MAC Table:** Maintains learned associations between MAC addresses, switch ports, and VLANs.
- **Source MAC Learning:** Switch learns source MAC address and associates it with ingress port.
- **Known Destination MAC:** Forwards frame to the corresponding destination port.
- **Unknown Destination MAC:** Floods frame to other appropriate ports within the same VLAN.
- **Same-Port Destination:** Filters forwarding when the destination resides on the incoming port.
- **Router/Layer 3 Switch:** Connects different IP networks or VLANs.

### 10.2 Virtual LANs

- **VLAN (Virtual Local Area Network):** Logical network segment configured on switching infrastructure.
- **Broadcast Domain:** A VLAN normally creates a separate Layer 2 broadcast domain.
- **Traffic Isolation:** Restricts ordinary Layer 2 communication between VLANs.
- **Traffic Management:** Reduces unnecessary broadcast traffic.
- **Flexibility:** Logical network membership can change without rearranging physical connections.
- **Inter-VLAN Routing:** Requires a router or Layer 3 switch.
- **IEEE 802.1Q:** VLAN tagging standard.
- **Access Port:** Commonly carries traffic for one VLAN.
- **Trunk Port:** Carries traffic for multiple VLANs.
- **Private VLAN:** Restricts communication between specified devices/ports within a VLAN.

**Critical distinction:** VLANs provide segmentation, NOT encryption.

### 10.3 Switch Attacks

#### MAC/CAM Flooding

- Attacker generates many fabricated source MAC addresses.
- Switch forwarding table may become exhausted.
- Some switches may start flooding unknown-unicast traffic.
- May expose traffic to unauthorized sniffing.

**Defense:** MAC address limits, switch port security, NAC/802.1X, and monitoring.

#### MAC Spoofing

- Attacker changes a device's MAC address.
- Can bypass weak MAC-based access restrictions.

**Defense:** Strong identity-based authentication and NAC.

#### VLAN Hopping

- Attacker attempts communication across VLAN boundaries without authorization.
- Can exploit misconfigured trunking or VLAN tag processing.

**Double-Tagging Attack:**
- Uses multiple VLAN tags.
- Can exploit native VLAN/trunk configuration weaknesses.

**Defense:**
- Disable unnecessary trunking.
- Disable automatic trunk negotiation where inappropriate.
- Use an unused/native VLAN not assigned to ordinary users.
- Restrict allowed VLANs on trunk ports.

#### ARP Poisoning

- Attacker introduces false IP-to-MAC mappings.
- Can redirect traffic and facilitate attacker-in-the-middle attacks.

**Defense:** Dynamic ARP Inspection, DHCP snooping support, monitoring, and encrypted communications.

### 10.4 Network Monitoring Methods

- **SPAN/Port Mirroring:** Copies switch traffic to another port for monitoring.
- **Network TAP:** Hardware device allowing observation of network traffic.

**Exam distinctions:**

- MAC flooding attacks the forwarding table.
- MAC spoofing attacks MAC-based identity assumptions.
- VLAN hopping attacks segmentation boundaries.
- VLANs do not replace firewalls or encryption.

## 11. NAT, PAT, Addressing, and Split DNS

### 11.1 NAT

- **NAT (Network Address Translation):** Rewrites IP addressing information.
- **Purpose:** Conserves public IPv4 addresses and enables private-to-public network communication.
- **Security Limitation:** NAT does not provide encryption or replace firewall controls.

### 11.2 NAT Types

- **Static NAT:**
  - Predefined mapping between addresses.
  - Often one private IP mapped to one public IP.
  - May operate without dynamically allocated session mappings.

- **Dynamic NAT:**
  - Assigns translations from a configured address pool.
  - Typically maintains active translation entries.

- **PAT (Port Address Translation):**
  - Also called NAT Overload or NAPT.
  - Multiple internal devices share one public IP.
  - Differentiates traffic using translated port numbers.

- **DNAT (Destination NAT):**
  - Translates destination address/port.
  - Commonly used to publish internal services.
  - Must be combined with appropriate inbound security policies.

- **Stateful NAT:**
  - Maintains active translation/session information.
  - Uses recorded mappings to forward returning traffic.

- **Stateless NAT:**
  - Uses predefined or algorithmic mappings.
  - Does not require per-session history for translation.

**Important:** Static NAT and stateless NAT are not synonymous. A device can implement static translations while maintaining stateful firewall sessions.

### 11.3 RFC 1918 Private IP Addresses

| Address Range | CIDR |
|---|---|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 |

- Private IPv4 addresses cannot be routed directly over the public Internet.

### 11.4 Special IPv4 Addresses

- **APIPA (169.254.0.0/16):**
  - IPv4 link-local addressing.
  - Commonly self-assigned when DHCP is unavailable.
  - Not part of RFC 1918 private addressing.

- **Loopback (127.0.0.0/8):**
  - Used for local TCP/IP communication.
  - Commonly `127.0.0.1`.
  - Not part of RFC 1918 private addressing.

### 11.5 Split DNS and Public Accessibility

- **Split DNS:** Provides different DNS responses depending on whether a query originates internally or externally.
- **DMZ/Screened Subnet:** Separates externally accessible services from sensitive internal systems.
- **Public DNS:** Must point external users to a publicly reachable endpoint.

**Exam scenario:**

A web server uses `172.31.201.17`. Internal users can access it, but external Internet users cannot.

**Reason:** The address belongs to RFC 1918 private IPv4 space. The externally published service requires a reachable public endpoint, such as an appropriately configured NAT or reverse proxy.

## 12. Third-Party and Cloud Connectivity

### 12.1 Third-Party Risks

- Interconnected organizations share exposure to security threats.
- Compromise of one network may facilitate compromise of another.
- Perform a risk assessment before establishing connectivity.
- Evaluate vendor/partner security requirements and responsibilities.

### 12.2 Agreements

- **MOU/MOA (Memorandum of Understanding/Agreement):**
  - Records shared intentions and expectations.
  - Typically nonbinding in the study-guide context.

- **ISA (Interconnection Security Agreement):**
  - Defines security requirements for connecting organizational networks.
  - Establishes responsibilities, risks, and technical security expectations.

### 12.3 Third-Party Security Controls

- **Least Privilege:** Grant only required access.
- **Network Segmentation:** Isolate third-party connections from sensitive networks.
- **VPN/Extranet:** Provide controlled access to shared resources.
- **CASB (Cloud Access Security Broker):** Enforces cloud security policies and provides visibility/control.
- **Managed Endpoints:** Prefer compliant devices for remote workers and partners.
- **Continuous Monitoring:** Review access, security posture, and changes in third-party risk.
- **Access Termination:** Revoke connectivity when relationships or business needs end.

**Exam distinction:** MOU documents mutual intentions; ISA defines security requirements for network interconnections.

## 13. Circuit Switching, Packet Switching, and Virtual Circuits

### 13.1 Circuit Switching

- Creates a dedicated communication path between endpoints for the duration of a session.
- Resources remain reserved throughout communication.
- Provides relatively predictable transmission delay.
- Can be inefficient when the reserved path is idle.
- A physical path failure can interrupt the session.

### 13.2 Packet Switching

- Divides communication into packets.
- Packets share network infrastructure.
- Improves bandwidth utilization.
- May experience variable delay, jitter, and packet loss.
- Alternate paths may be available following network failures.
- Shared communication paths create confidentiality risks without appropriate encryption.

**Important:** Packet-switched networks can support connection-oriented protocols such as TCP. Packet switching does not necessarily mean connectionless communication.

### 13.3 Virtual Circuits

- **Virtual Circuit:** Logical communication association across packet-switched infrastructure.
- **PVC (Permanent Virtual Circuit):** Predefined logical circuit that remains available for communication.
- **SVC (Switched Virtual Circuit):** Established on demand and terminated after communication.

| Feature | PVC | SVC |
|---|---|---|
| Establishment | Preconfigured | On demand |
| Availability | Continuously available logically | Established when needed |
| Termination | Generally remains configured | Released after use |

**Exam distinction:** A logical circuit that always exists and waits for traffic is a **PVC**.

## 14. WAN Technologies, Fault Tolerance, and Fiber

### 14.1 WAN Connections

- **WAN (Wide Area Network):** Connects geographically separated systems or networks.
- **Dedicated/Leased Line:** Reserved point-to-point connection between specified endpoints.
- **Nondedicated Line:** Requires connection establishment when needed; legacy dial-up is an example.
- **MPLS (Multiprotocol Label Switching):**
  - Uses labels for packet forwarding.
  - Supports traffic engineering and QoS.
  - Does not inherently provide encryption.
- **SD-WAN:**
  - Software-defined management of WAN connectivity.
  - Supports policy-based routing and dynamic path selection.
- **SONET/SDH:**
  - Related synchronous high-speed optical networking standards.
  - Used for carrier infrastructure.
- **Backhaul:** Connects access/local networks to a broader network or core infrastructure.

### 14.2 Legacy WAN Technologies

- **T1/DS3:** Legacy leased-line services.
- **Frame Relay:** Legacy packet-switched WAN technology.
- **ATM:** Uses fixed-size cells.
- **X.25:** Legacy packet-switched WAN technology.
- **ISDN:** Legacy digital telecommunications technology.

### 14.3 WAN Redundancy

- Maintain multiple network connections.
- Use different telecom providers where practical.
- Ensure physically separate cable paths.
- Avoid common carrier backbones and shared network facilities.
- Test failover procedures.
- Maintain fallback connections where required.

**Critical distinction:** Two different service providers may still share infrastructure and therefore represent a single point of failure.

**WAN Security:** Dedicated circuits and MPLS services do not automatically provide cryptographic confidentiality.

## 15. Network Attack Detection and Prevention

### 15.1 Eavesdropping

- **Eavesdropping:** Unauthorized interception or copying of communications.
- Typically a **passive attack**.
- Primarily threatens confidentiality.
- Can involve sniffers, unauthorized monitoring, or physical wiretapping.

**Controls:**
- Encryption using TLS, IPSec, or SSH.
- Physical protection of network infrastructure.
- Secure endpoint and administrative access.
- Monitoring for unauthorized sniffing tools.

### 15.2 Modification Attacks

- **Modification Attack:** Unauthorized alteration or injection of transmitted packets.
- Classified as an **active attack**.
- Primarily threatens integrity and authenticity.

**Controls:**
- Cryptographic MAC/HMAC.
- Digital signatures.
- Authenticated encryption.
- Peer authentication.

**Important:** Ordinary checksums and CRCs primarily detect accidental errors and do not provide strong protection against malicious modifications.

### 15.3 Replay Attacks

- Attacker captures valid messages and retransmits them later.
- May bypass systems lacking freshness verification.

**Controls:**
- Nonces.
- Timestamps.
- Sequence numbers.
- Anti-replay windows.

### 15.4 Impersonation and Spoofing

- **Impersonation:** Pretending to be a legitimate user or system.
- **Spoofing:** Falsifying identifying information, such as IP, MAC, email address, or Caller ID.

**Controls:** Strong authentication, certificate validation, and source validation.

### 15.5 Denial of Service

- **DoS:** Disrupts service availability.
- **DDoS:** Distributed denial-of-service attack originating from multiple sources.

**Controls:** Rate limiting, upstream filtering, capacity management, redundancy, and DDoS mitigation services.

### 15.6 ARP and DNS Poisoning

- **ARP Poisoning:** Introduces false IP-to-MAC mappings to redirect local traffic.
- **DNS Poisoning:** Manipulates name-resolution results to redirect users.

**Controls:** Secure protocols, DNSSEC where applicable, network protections, and monitoring.

### 15.7 Multilayer Protocol Risks

- **Encapsulation:** Wrapping protocol data within another protocol.
- **Multiple Encapsulation:** Nesting protocols within other protocols.
- **Tunneling-Based Filter Evasion:** Hiding traffic inside permitted protocols to bypass inspection.
- **VLAN Hopping:** Exploiting VLAN encapsulation or switching configurations to cross logical boundaries.
- **IP Fragmentation Abuse:** Using fragmented packets to evade inadequate security inspection.

**Exam distinction:** Static IP addressing is not inherently an implication of multilayer protocols.

## 18. Scenario-Based Revision

### Scenario 1 — Private IP Accessibility

A public website points to `192.168.6.25`.

**Explanation:** This is a private RFC 1918 address. An external user needs a publicly reachable service endpoint or approved private connectivity.

### Scenario 2 — PBX Toll Fraud

Unauthorized international calls are originating from a company PBX.

**Explanation:** Investigate compromised credentials and remote dialing features. Change default passwords, restrict calling privileges, and review logs.

### Scenario 3 — VLAN Security

Management wants to isolate departments without changing physical cabling.

**Explanation:** VLANs provide configurable Layer 2 segmentation but do not encrypt traffic.

### Scenario 4 — VPN Availability

Two organizations want a VPN, but their networks have no existing communication path.

**Explanation:** A VPN cannot create physical connectivity. An underlying network must exist.

### Scenario 5 — Dedicated Line Security

An organization assumes its leased line guarantees confidentiality.

**Explanation:** A dedicated connection does not inherently provide encryption. Sensitive traffic may require cryptographic protection.

### Scenario 6 — Poor Network Performance

Users experience call interruptions despite having high bandwidth.

**Explanation:** Investigate latency, jitter, throughput, packet loss, interference, and SNR.

### Scenario 7 — WAN Failover

Two ISP connections enter the same physical cable duct.

**Explanation:** A single physical incident may affect both. Separate the physical routes.

### Scenario 8 — Email Retention

The organization must preserve emails for seven years.

**Explanation:** Configure retention, archival, authorized review, legal holds, and secure disposal. Ordinary backups alone may not satisfy recordkeeping requirements.

### Scenario 9 — MAC Flooding

A switch receives frames with thousands of fabricated source MAC addresses.

**Explanation:** The forwarding table may become exhausted, causing unknown-unicast flooding. Apply port security and MAC limits.

### Scenario 10 — Tunneling Evasion

A firewall allows a permitted tunnel containing prohibited inner traffic.

**Explanation:** Encapsulation can hide inner traffic from filters inspecting only the outer protocol. Apply tunnel inspection and appropriate restrictions.

## 19. Five-Minute CISSP Revision Checklist

- [ ] Transparency = Security operates without unnecessary user disruption.
- [ ] PAP = Plaintext credentials.
- [ ] CHAP = Challenge-response.
- [ ] EAP = Authentication framework.
- [ ] 802.1X = Port-based network admission control.
- [ ] NAC = Endpoint authentication/compliance.
- [ ] Port security = Physical, logical, and TCP/UDP controls.
- [ ] QoS = Bandwidth, throughput, latency, jitter, packet loss, interference, SNR.
- [ ] Phreaking = Telephone/PBX exploitation.
- [ ] PBX prevention = Change defaults and restrict access/dialing.
- [ ] Collaboration = Encryption, MFA, logging.
- [ ] S/MIME/PGP = Email encryption and signatures.
- [ ] SPF = Authorized sending servers.
- [ ] DKIM = Domain signing.
- [ ] DMARC = SPF/DKIM alignment and policy.
- [ ] Email retention != Ordinary backup.
- [ ] VPN = Requires existing connectivity.
- [ ] IPSec Transport = Original IP header remains.
- [ ] IPSec Tunnel = Entire original packet protected with ESP encryption.
- [ ] AH = Authentication and integrity; no encryption.
- [ ] ESP = Confidentiality and optional authentication/integrity.
- [ ] IKE = Key negotiation.
- [ ] VLAN = Segmentation; not encryption.
- [ ] MAC flooding = Forwarding table exhaustion.
- [ ] VLAN hopping = Unauthorized traffic crossing VLAN boundaries.
- [ ] RFC1918 = 10/8, 172.16/12, 192.168/16.
- [ ] APIPA = 169.254/16; not RFC1918.
- [ ] NAT = Address translation, not encryption.
- [ ] PAT = Many-to-one translation using ports.
- [ ] MOU = Mutual intentions.
- [ ] ISA = Interconnection security requirements.
- [ ] Circuit switching = Dedicated communication path.
- [ ] Packet switching = Shared communication paths.
- [ ] PVC = Permanent virtual circuit.
- [ ] SVC = On-demand virtual circuit.
- [ ] WAN redundancy = Multiple providers and physically separate paths.
- [ ] Passive eavesdropping = Confidentiality threat.

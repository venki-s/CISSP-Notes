## 1. Protocol Security Mechanisms

- **TCP/IP:** Primary networking protocol suite; additional security protocols are needed for confidentiality, integrity, and authentication.
- **PPP (Point-to-Point Protocol):** Layer 2 protocol for point-to-point connections; supports authentication, link configuration, and error detection.

### 1.1 Authentication Protocols

- **PAP (Password Authentication Protocol):** Sends usernames and passwords in cleartext; insecure.
- **CHAP (Challenge Handshake Authentication Protocol):** Uses challenge-response authentication and periodic reauthentication; legacy and no longer considered secure.
- **EAP (Extensible Authentication Protocol):** Authentication framework supporting multiple authentication methods.

### 1.2 EAP Methods

- **LEAP:** Cisco proprietary authentication method; insecure and deprecated.
- **PEAP:** Protects EAP authentication inside a TLS tunnel; supports mutual authentication.
- **EAP-TLS:** Uses TLS and digital certificates; supports mutual certificate authentication.
- **EAP-TTLS:** Creates a TLS tunnel before authenticating the client; protects credentials.
- **EAP-SIM:** Uses SIM credentials for mobile network authentication.
- **EAP-FAST:** Cisco-developed secure tunneling method intended to replace LEAP.
- **EAP-MD5:** Uses MD5-based authentication; deprecated.
- **EAP-POTP:** Supports one-time passwords (OTP).
- **EAP-IKEv2:** Uses IKEv2 for authentication and session key establishment.
- **EAP-NOOB:** Uses out-of-band methods (QR codes, NFC) for onboarding devices without existing credentials.

### 1.3 IEEE 802.1X

- **802.1X:** Port-based network access control; requires authentication before granting network access.
- **802.1X + EAP:** Enables enterprise authentication through an AAA server.
- **Security Concern:** Some methods are vulnerable to session hijacking; use secure EAP methods and reauthentication.

### 1.4 Port Security

- **Physical Port Security:** Disable unused network ports and restrict access to switches, patch panels, and wiring closets.
- **TCP/UDP Port Security:** Close unused service ports; monitor and restrict port scanning.

### 1.5 Quality of Service (QoS)

- **QoS:** Manages network traffic to maintain performance and availability.
- **Bandwidth:** Network capacity.
- **Latency:** Time taken for data to travel from source to destination.
- **Jitter:** Variation in packet delay.
- **Packet Loss:** Packets lost during transmission.
- **Throughput:** Actual successfully transmitted data per unit of time.
- **SNR (Signal-to-Noise Ratio):** Signal strength compared with background noise; higher is better.
- **Traffic Prioritization:** Gives time-sensitive traffic (e.g., VoIP) higher priority.
- **Traffic Shaping/Throttling:** Controls traffic rates to reduce congestion.
- **Security Relevance:** QoS supports **Availability** in the CIA Triad.


## 2. Secure Voice Communications

- **PSTN (Public Switched Telephone Network):** Traditional telephone network; vulnerable to interception and eavesdropping.
- **PBX (Private Branch Exchange):** Private telephone switching system used within organizations, single number with extensions.
- **VoIP (Voice over IP):** Transmits voice communications over IP networks.
- **SRTP (Secure Real-Time Transport Protocol):** Provides encryption for VoIP communications.
- **VoIP Encryption:** Not necessarily end-to-end; calls passing through gateways may be decrypted and re-encrypted.

### 2.1 Voice Communication Attacks

- **Vishing (Voice Phishing):** Social engineering through phone calls, often using spoofed Caller ID.
- **Phreaking:** Exploiting telephone systems to make unauthorized calls, steal services, or disrupt communications.
- **PBX Fraud:** Unauthorized use of PBX services, including toll fraud, call redirection, and voicemail access.
- **VoIP Risks:** Eavesdropping, AitM, session hijacking, and DoS attacks.

### 2.2 Security Controls

- **Callback Verification:** Verify sensitive telephone requests by calling back using a trusted, predefined number.
- **Caller ID Spoofing:** Caller ID can be forged; never rely on it for authentication.
- **DISA (Direct Inward System Access):** Allows authenticated external access to PBX services.
- **PBX Security:** Restrict remote dialing, change default passwords, disable unused features, and audit call activities.
- **VoIP Security:** Use strong authentication, encryption, firmware updates, and call monitoring.


## 3. Remote Access Security Management

- **Telecommuting:** Performing work remotely using VPNs, remote desktops, VDI, or cloud services.

### 3.1 Remote Access Techniques

- **Service-Specific Access:** Provides remote access to a single service (e.g., email).
- **Remote Control:** Allows a user to control a distant computer.
- **Remote Node Operation:** Connects a remote device directly to a LAN through VPN, wireless, or dial-up.

### 3.2 Remote Access Security Controls

- **Strong Authentication:** Require MFA and secure authentication protocols.
- **Encryption:** Use VPN or TLS to protect remote communications and credentials.
- **Least Privilege:** Grant remote access only to authorized users who need it.
- **Endpoint Security:** Ensure remote devices meet security requirements.
- **NAC:** Verify endpoint compliance before permitting network access.
- **Access Restrictions:** Restrict connections based on identity, device, application, protocol, and time.
- **Disable Unauthorized Connections:** Prohibit unauthorized modems, wireless adapters, or secondary network connections.
- **Remote Access Policy:** Define permitted connectivity methods, authentication, encryption, monitoring, and user support.

### 3.3 Remote Access Risks

- **Insecure Endpoints:** Remote devices may lack adequate security controls.
- **Malware:** Compromised remote devices can introduce malware into internal networks.
- **Physical Security:** Remote devices are more vulnerable to theft and unauthorized use.
- **Patch Management:** Remote systems may not receive timely updates.

### 3.4 Remote Network Administration

- **Remote Administration:** Managing network devices, security policies, accounts, updates, backups, and monitoring remotely.
- **Security Requirement:** Administrative remote access must follow organizational security policies and use secure connections.

### 3.5 Multimedia Collaboration Security

- **Multimedia Collaboration:** Remote communication through video conferencing, chat, file sharing, whiteboards, and shared documents.

### 3.6 Security Considerations

- **Authentication:** Require strong authentication and MFA.
- **Encryption:** Verify whether communications are encrypted end-to-end or only between the client and server.
- **Access Control:** Prevent unauthorized participants from joining meetings.
- **Logging and Auditing:** Monitor user activities and security events.
- **Data Protection:** Control recording access, sharing, retention, and deletion.
- **Vendor Assessment:** Evaluate collaboration platforms against organizational security policies.

### 3.7 Instant Messaging (IM) Security

- **Instant Messaging:** Real-time text communication, sometimes supporting file transfers and multimedia.
- **Risks:** Eavesdropping, malware through file transfers, impersonation, social engineering, and information disclosure.
- **Controls:** Encryption, MFA, logging, access restrictions, and centrally managed communication platforms.


## 4. Network Monitoring and Load Balancing

- **Network Observability:** Uses metrics, logs, and traces to detect network issues.
- **Traffic Shaping:** Prioritizes and controls traffic to prevent congestion.
- **Capacity Management:** Ensures sufficient resources for current and future network demands.
- **Fault Management:** Detects failures and supports recovery to maintain availability.

### 4.1 Load Balancing
- **Load Balancing:** Distributes workload across multiple systems to improve performance and availability.
- **Round Robin:** Distributes requests sequentially.
- **Weighted:** Distributes requests based on server capacity or priority.
- **Least Connections:** Selects the server with the fewest active connections.
- **Session Affinity (Persistence):** Directs requests from the same client to the same server.
- **VIP (Virtual IP):** Single logical IP representing multiple backend servers.
- **GSLB:** Distributes traffic across geographically separated data centers.
- **TLS Offloading:** Load balancer handles TLS encryption/decryption instead of backend servers.

### 4.2 High Availability
- **Active-Active:** All systems operate simultaneously; remaining systems handle traffic after a failure, possibly with reduced capacity.
- **Active-Passive:** Standby system takes over when the active system fails.


## 5. Virtual Private Network (VPN)

- **VPN:** Creates a logical communication channel over an untrusted network.
- **Security:** Can provide confidentiality, integrity, authentication, and access control.
- **VPN Encryption:** Commonly used but not mandatory for a connection to qualify as a VPN.
- **VPN Concentrator:** Handles multiple simultaneous VPN connections.
- **VPN Limitation:** Does not guarantee availability.

### 5.1 Tunneling
- **Tunneling:** Encapsulates one protocol's packets inside another protocol.
- **Encryption:** Tunneling alone does not guarantee confidentiality.
- **Risks:** Additional bandwidth overhead and difficulty inspecting encrypted traffic.

### 5.2 VPN Operating Modes (IPSec)
- **Transport Mode:** Protects the IP payload; original IP header remains visible.
  - Commonly used for host-to-host communication.
- **Tunnel Mode:** Protects the entire original IP packet and adds a new IP header.
  - Commonly used for site-to-site and remote-access VPNs.

### 5.3 VPN Traffic Routing
- **Split Tunnel:** Corporate traffic uses VPN; Internet traffic goes directly.
  - **Risk:** Bypasses corporate security controls.
- **Full Tunnel:** All client traffic passes through the VPN and corporate security infrastructure.
  - **Benefit:** Centralized filtering and monitoring.
- **Always-On VPN:** Automatically establishes VPN connectivity when network access becomes available.

### 5.4 VPN Protocols

- **PPTP (TCP 1723):** Legacy tunneling protocol; insecure and obsolete.
- **L2TP (UDP 1701):** Layer 2 tunneling; no native encryption.
  - Commonly combined with IPSec for encryption.
- **GRE:** Encapsulation protocol; does not provide encryption.
- **SSH (TCP 22):** Encrypted remote access and tunneling.
- **OpenVPN:** TLS-based VPN supporting certificate or pre-shared-key authentication.
- **IPSec:** Suite of protocols securing IP communications through authentication, encryption, and integrity protection.

### 5.5 IPSec Components

- **AH (Authentication Header):**
  - Provides authentication, integrity, and anti-replay protection.
  - Does NOT provide encryption/confidentiality.

- **ESP (Encapsulating Security Payload):**
  - Provides confidentiality through encryption.
  - Supports integrity, authentication, and anti-replay protection.

- **IKE (Internet Key Exchange):**
  - Negotiates security parameters and establishes cryptographic keys.

- **SA (Security Association):**
  - Defines agreed security parameters for communication.
  - IPSec SAs are unidirectional; bidirectional communication requires two SAs.

- **HMAC:** Provides message integrity and authentication.


## 6. Network Address Translation (NAT)

- **NAT:** Translates private IP addresses into public IP addresses.
- **Purpose:** Conserves public IPv4 addresses and hides internal network addressing.
- **NAT (Traditional):** One-to-one IP address translation.
- **PAT (Port Address Translation):** Many internal devices share one public IP using different port numbers.
  - Also called NAT Overload or NAPT.
- **Stateful NAT:** Maintains connection mappings to forward responses to the correct internal device.
- **Static NAT / DNAT:** Maps a public address to an internal system, allowing inbound connections.
  - **Risk:** Exposes internal systems to external access.
- **NAT-T (NAT Traversal):** Allows IPSec VPN traffic to pass through NAT devices.
- **NAT66:** IPv6 address translation; generally less necessary due to IPv6's large address space.
- **Security Limitation:** NAT hides internal addresses but does not replace a firewall or provide encryption.

### 6.1 Private IPv4 Addresses (RFC 1918)

- **10.0.0.0/8:** 10.0.0.0 – 10.255.255.255
- **172.16.0.0/12:** 172.16.0.0 – 172.31.255.255
- **192.168.0.0/16:** 192.168.0.0 – 192.168.255.255
- **Private IPs:** Not directly routable over the public Internet.

### 6.2 Special IP Addresses

- **APIPA (169.254.0.0/16):** Automatically assigned link-local address when DHCP fails.
  - Allows local communication but not normal routed Internet access.
- **Loopback (127.0.0.1):** Tests local TCP/IP communication without using the physical network.
  - Entire 127.0.0.0/8 range is reserved for loopback.


## 7. Switching Technologies

### 7.1 Circuit Switching
- **Circuit Switching:** Establishes a dedicated communication path between two endpoints for the entire session.
- **Advantages:** Predictable latency and consistent communication quality.
- **Disadvantages:** Inefficient resource utilization; connection fails if the dedicated path is disrupted.

### 7.2 Packet Switching
- **Packet Switching:** Divides data into packets transmitted over shared network paths.
- **Advantages:** Efficient bandwidth utilization and ability to use alternate paths during failures.
- **Disadvantages:** Variable latency, packet loss, and potential eavesdropping on shared connections.
- **Security:** Requires traffic isolation and encryption to protect communications.

### 7.3 Virtual Circuits
- **Virtual Circuit:** Logical communication path established over a packet-switched network.
- **PVC (Permanent Virtual Circuit):** Predefined logical path that remains available for communication.
- **SVC (Switched Virtual Circuit):** Established when needed and terminated after communication.


### 7.4 WAN Security
- **Dedicated Line:** Reserved point-to-point connection.
- **Nondedicated Line:** Connection established when needed.
- **WAN Redundancy:** Use multiple providers and physically separate paths to avoid single points of failure.
- **WAN Security:** Encrypt communications over untrusted networks.

### 7.5 Network Attacks
- **Eavesdropping:** Passive interception of network traffic to obtain confidential information.
  - **Defense:** Encryption (IPSec/SSH) and physical access controls.
- **Modification Attack:** Active attack involving alteration of intercepted packets.
  - **Defense:** Cryptographic integrity checks and digital signatures.

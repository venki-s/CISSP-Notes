
# Chapter 17 — Preventing and Responding to Incidents

**CISSP Domain:** 7 — Security Operations

---

## 1. Security Incident Management

### Security Incident
- An event that violates or threatens security policies, acceptable-use policies, or standard security practices.
- May compromise confidentiality, integrity, or availability (CIA).
- **Event:** Observable occurrence; not every event is an incident.
- **Incident:** Confirmed or reasonably suspected security violation requiring a response.

### Primary Goal
- Minimize organizational impact by rapidly detecting, containing, and responding to security incidents.

### Incident Management — Seven Steps

1. **Detection:** Identify and validate potential security incidents.
2. **Response:** Activate appropriate personnel and incident response procedures.
3. **Mitigation:** Contain the incident and limit its impact or spread.
4. **Reporting:** Notify management, affected parties, and regulators as required.
5. **Recovery:** Restore affected systems and business operations.
6. **Remediation:** Identify root causes and implement corrective controls.
7. **Lessons Learned:** Review incident handling and improve future prevention and response.

### Critical Distinctions
- **Detection:** Determine whether an alert represents a real incident.
- **Response:** Mobilize the incident response team (CIRT/CSIRT).
- **Mitigation:** Isolate infected systems or block malicious traffic.
- **Recovery:** Restore systems to trusted operational condition.
- **Remediation:** Correct vulnerabilities or conditions that enabled the incident.
- **Lessons Learned:** Improve policies, procedures, training, and detection capabilities.

### Important Principles
- Preserve evidence for potential investigation and prosecution.
- Avoid unnecessarily powering off compromised systems because volatile evidence may be lost.
- Isolation from the network can contain an incident while preserving memory.
- Actions must consider safety, business impact, and forensic requirements.
- Do not conduct unauthorized counterattacks or hack back.

**Exam:** Containment limits current damage; remediation prevents recurrence.

---

## 2. Incident Reporting and Evidence Protection

- Escalate significant incidents according to the incident response plan.
- Follow applicable legal, regulatory, contractual, and privacy notification requirements.
- Notify affected individuals when required by applicable law.
- Preserve relevant logs, system information, and other evidence.
- Protect evidence integrity and support chain-of-custody procedures.

### First Responders
- Investigate initial alerts.
- Distinguish ordinary operational problems from security incidents.
- Escalate confirmed or suspected incidents.
- Avoid unnecessary modification or destruction of evidence.

### Root Cause Analysis (RCA)
- Determines why an incident occurred.
- Identifies underlying control failures.
- Supports remediation and prevention of repeated incidents.

## 3. Preventive vs. Detective Controls

| Preventive Controls | Detective Controls |
|---|---|
| Attempt to prevent incidents | Identify incidents or violations |
| Firewalls | IDS |
| IPS | Audit logs |
| Access controls | Honeypots |
| Anti-malware blocking | Security monitoring |
| Encryption | Incident investigations |

- Some controls serve multiple purposes depending on implementation.
- **IDS:** Primarily detective.
- **IPS:** Primarily preventive, with detection capabilities.

## 4. Denial-of-Service Attacks

### DoS vs. DDoS
- **DoS:** Attempts to make a service unavailable, commonly from one attack source.
- **DDoS:** Multiple distributed systems attack the same target.
- **Botnet:** Network of compromised devices controlled by an attacker.
- **Bot Herder:** Attacker controlling a botnet.
- **Command and Control (C2):** Infrastructure used to issue instructions to compromised systems.

### Common DoS Attacks

| Attack | Mechanism |
|---|---|
| SYN Flood | Sends SYN packets without completing TCP handshake |
| TCP Reset | Sends forged RST packets to terminate connections |
| Smurf | Spoofed ICMP requests cause replies to flood victim |
| Fraggle | Similar to Smurf but uses UDP |
| Ping Flood | Overwhelms target with ICMP echo requests |
| DRDoS | Uses third-party reflectors to direct traffic at victim |

### SYN Flood
- Exploits TCP's three-way handshake.
- Creates numerous incomplete connections.
- Consumes server resources.

**Mitigation:**
- SYN cookies.
- Connection timeout adjustments.
- Firewall/IPS protections.

### Smurf vs. Fraggle
- **Smurf:** ICMP-based broadcast amplification.
- **Fraggle:** UDP-based broadcast amplification.
- Both rely on spoofed source addresses.
- Blocking directed broadcasts helps mitigate these attacks.

### Legacy DoS Attacks
- **Ping of Death:** Oversized/malformed ping packets.
- **Teardrop:** Malformed or overlapping packet fragments.
- **LAND:** Spoofed packets using the victim's IP as both source and destination.

**Exam:** Reflection uses third-party systems; amplification increases attack traffic volume.

## 5. Other Security Attacks

### Zero-Day Exploit
- Exploits a vulnerability before an effective fix is available, typically before public disclosure or patch availability.
- Signature-based security controls may not recognize the attack.
- Mitigations include defense in depth, minimizing attack surface, monitoring, and IPS protections.

**Important:** Exploitation of a long-known vulnerability on an unpatched system is not a zero-day attack.

### Man-in-the-Middle (MiTM) / On-Path Attack
- Attacker intercepts communications between two endpoints.
- May monitor, alter, or relay traffic.
- Can involve DNS, ARP, or routing manipulation.

**Mitigations:** Secure protocols, certificate validation, authenticated encryption, and appropriate VPN protection.

### Insider Sabotage
- Deliberate damage or disruption by an authorized insider.
- Mitigations include:
  - Least privilege.
  - Monitoring privileged activity.
  - Separation of duties.
  - Timely access revocation during termination.

## 6. Intrusion Detection and Prevention Systems (IDPS)

### IDS vs. IPS

| IDS | IPS |
|---|---|
| Detects suspicious activity | Detects and blocks suspicious activity |
| Primarily sends alerts | Can actively prevent attacks |
| Commonly out-of-band | Typically inline |
| Detective control | Preventive and detective control |

### Detection Methods

#### Knowledge-Based / Signature-Based
- Matches activity against known attack signatures.
- Effective against recognized attacks.
- Generally produces fewer false positives.
- May miss unknown or modified attacks.
- Requires signature updates.

#### Behavior-Based / Anomaly-Based
- Compares current activity against a normal baseline.
- Can detect previously unknown attacks.
- May produce more false positives.
- Requires baseline tuning.

### Critical Comparison
- **Signature-Based:** Known attack patterns.
- **Anomaly-Based:** Deviations from normal behavior.

---

## 7. IDS Detection Outcomes

| Actual Condition | Alert Generated | Result |
|---|---|---|
| Attack occurred | Yes | True Positive |
| No attack occurred | Yes | False Positive |
| Attack occurred | No | False Negative |
| No attack occurred | No | True Negative |

### Important
- **False Positive:** Unnecessary investigation and alert fatigue.
- **False Negative:** Attack remains undetected.
- Excessive false positives may cause administrators to ignore legitimate alerts.
- Continuous tuning balances detection accuracy and operational workload.

### IDS Responses
- **Passive Response:** Log activity and notify administrators.
- **Active Response:** Modify the environment to block suspicious activity.

**Exam:** An inline IPS can stop traffic before it reaches the target; an out-of-band IDS generally cannot.

---

## 8. Host-Based vs. Network-Based IDS

### Host-Based IDS (HIDS)
- Monitors one host.
- Examines processes, system events, files, and logs.
- Can detect host-specific compromises.
- Consumes host resources.
- May be disabled by an attacker controlling the host.

### Network-Based IDS (NIDS)
- Monitors network traffic.
- Can observe multiple hosts.
- Uses network taps, sensors, or port mirroring.
- May not determine whether an exploit succeeded on a particular host.

### Monitoring Encrypted Traffic
- NIDS may not inspect encrypted payloads without decryption.
- TLS inspection can expose content for security analysis.
- Data encrypted before TLS transmission may remain unreadable.
- Traffic metadata may still reveal suspicious patterns.

**Exam:**
- Detect compromised files/processes → HIDS.
- Monitor traffic across a network segment → NIDS.
- Block malicious packets inline → NIPS.

## 9. Honeypots and Honeynets

### Honeypot
- Decoy system intended to attract unauthorized activity.
- Helps detect intrusions and study attacker behavior.
- Normally contains no genuine valuable information.

### Honeynet
- Network of multiple honeypots.

### Pseudo-Flaw
- Intentionally created apparent vulnerability designed to attract attackers.

### Enticement vs. Entrapment
- **Enticement:** Presenting an attractive target without inducing unlawful behavior.
- **Entrapment:** Improperly inducing someone to commit an offense; legal application depends on jurisdiction.

### Security Risks
- Attackers may attempt to use compromised honeypots to attack other systems.
- Honeypots require isolation and monitoring.

**Exam:** Decoy system for detecting and observing attackers → Honeypot.

## 10. Additional Preventive Measures

### Anti-Malware
- Uses signatures, heuristics, and behavioral analysis.
- Requires regular updates.
- Should be combined with other controls through defense in depth.

### Application Allowlisting vs. Denylisting
- **Allowlist:** Only explicitly approved applications may execute.
- **Denylist:** Explicitly prohibited applications are blocked; other applications may execute.
- Allowlisting generally provides stronger default restrictions against unknown applications.

### Sandboxing
- Executes untrusted code in an isolated environment.
- Limits interaction with production systems.
- Can be used to observe suspicious applications or malware.

### Security Firewalls
- **WAF:** Protects web applications against application-layer attacks, including SQL injection and XSS.
- **NGFW:** Combines traditional filtering with deeper inspection and other security capabilities.
- **Implicit Deny:** Block traffic not explicitly permitted.

### Third-Party Security Services
- Security functions may be outsourced.
- The organization retains accountability for applicable security and compliance obligations.

## 11. Logging and Monitoring

### Logging
- Records system activities and security events.
- Supports accountability, investigation, and incident reconstruction.

### Monitoring
- Reviews activity to identify suspicious behavior or failures.

### Common Log Types

| Log | Records |
|---|---|
| Security | Authentication, access, privilege use |
| System | Startup, shutdown, service/system events |
| Application | Application-specific events |
| Firewall | Allowed and blocked network traffic |
| Proxy | Website access and proxy activity |
| Change | Configuration changes and approvals |

### Log Protection
- Protect logs against unauthorized modification and deletion.
- Centralize important logs.
- Restrict access.
- Apply appropriate retention and archival policies.
- Synchronize timestamps using **NTP**.

### Audit Trails
- Reconstruct activities before, during, and after incidents.
- Support investigations and accountability.
- Require reliable identification and authentication.

**Exam:** Reliable logs must support integrity, accountability, and accurate timestamps.

## 12. SIEM and Syslog

### Security Information and Event Management (SIEM)
- Collects and centralizes logs from multiple sources.
- Aggregates and correlates events.
- Detects suspicious patterns.
- Generates alerts.
- Supports investigations and historical analysis.

### Syslog
- Standardized protocol for forwarding event messages.
- Defined in RFC 5424.
- Commonly used for centralized log collection.

### SIEM vs. Syslog
- **Syslog:** Transports/formats event messages.
- **SIEM:** Collects, correlates, analyzes, and alerts on events.

### Continuous Monitoring and Tuning
- Regularly review security events.
- Adjust detection thresholds and signatures.
- Update behavior baselines as environments change.
- Reduce false positives without creating excessive false negatives.

---

## 13. Sampling and Clipping Levels

### Statistical Sampling
- Selects representative data using statistical methods.
- Supports measurable confidence and error estimates.

### Nonstatistical Sampling
- Uses judgment or predefined selection criteria.
- May not represent the entire population.

### Clipping Level
- Threshold at which a monitoring system generates an alert.
- Helps avoid alerts for routine events.

**Example:** Alert after five failed login attempts within 30 minutes.

### Exam Distinction
- Statistical sampling = Mathematically based selection.
- Clipping level = Alert only after a threshold is exceeded.

---

## 14. Log Management

- Includes collection, protection, retention, archiving, and disposal of logs.
- Centralized logs support incident investigations.
- Retention periods should meet legal and organizational requirements.

### Rollover / Circular Logging
- Overwrites oldest events when maximum log size is reached.
- Risks losing evidence if events are not preserved elsewhere.

### Archival Logging
- Saves old logs before starting new logs.
- Preserves historical evidence.
- Requires storage capacity and retention management.

**Exam:** Protect audit logs from modification and preserve them for the required retention period.

---

## 15. Egress Monitoring and Data Exfiltration

### Egress Monitoring
- Monitors outbound network traffic.
- Helps detect unauthorized data transfers.

### Data Loss Prevention (DLP)
- Detects or blocks unauthorized movement of sensitive information.

### Steganography
- Conceals information inside another file or medium.
- Can be used to hide exfiltrated data.

### Digital Watermarking
- Embeds identifiable information within digital content.
- Can help trace unauthorized distribution.

### Encrypted Exfiltration
- Encryption may prevent payload inspection.
- Monitoring can still analyze:
  - Traffic volume.
  - Destination.
  - Source.
  - Frequency and unusual patterns.

**Exam:** Monitoring traffic leaving the organization → Egress Monitoring.

---

## 16. Security Orchestration, Automation, and Response (SOAR)

### SOAR
- Integrates security tools and automates response workflows.
- Reduces repetitive manual activities.
- Uses predefined incident handling procedures.

### Playbook vs. Runbook
- **Playbook:** Documented incident verification and response procedure.
- **Runbook:** Automated implementation of those procedures.

### SIEM vs. SOAR
- **SIEM:** Event collection, correlation, detection, and alerting.
- **SOAR:** Workflow orchestration and automated incident response.

### Important
- Automation should follow approved response policies.
- Incorrect detections can trigger inappropriate automated actions.
- Human oversight may still be necessary.

---

## 17. Machine Learning and AI in Security

### Machine Learning (ML)
- Subset of AI.
- Learns patterns from data.
- Can improve detection using experience and feedback.

### Artificial Intelligence (AI)
- Broader field that includes ML.
- Supports intelligent analysis, anomaly detection, and security automation.

### Security Applications
- Behavioral anomaly detection.
- Threat identification.
- Alert prioritization.
- Detection tuning.

### Limitations
- False positives and false negatives remain possible.
- Results depend on data quality, training, and tuning.

## 18. Threat Intelligence and Threat Hunting

### Threat Intelligence
- Collection and analysis of information about threats.
- Supports proactive defensive decisions.

### Threat Feeds
May contain:
- Malicious IP addresses.
- Suspicious domains.
- Malware hashes.
- Known attack indicators.

### Threat Hunting
- Proactive searching for threats that have not triggered alerts.
- Assumes attackers may already be present in the environment.
- Uses threat intelligence, logs, and attacker behavior.

### Critical Distinction
- **Threat Monitoring:** Observe and respond to detected indicators.
- **Threat Hunting:** Proactively search for undetected attacker activity.

## 19. Cyber Kill Chain

Lockheed Martin's Cyber Kill Chain describes seven ordered attack stages:

1. **Reconnaissance:** Gather target information.
2. **Weaponization:** Prepare an exploit and malicious payload.
3. **Delivery:** Deliver the malicious payload.
4. **Exploitation:** Exploit a vulnerability.
5. **Installation:** Install malicious code or persistence mechanisms.
6. **Command and Control (C2):** Establish remote attacker control.
7. **Actions on Objectives:** Perform theft, destruction, or other intended actions.

### Security Purpose
- Identify opportunities to interrupt an attack.
- Preventing an attacker from advancing can stop the attack chain.

**Exam:** Ordered stages of an attack → Cyber Kill Chain.

## 20. MITRE ATT&CK

### Definition
- Knowledge base of adversary tactics, techniques, and procedures (TTPs).
- Organizes documented attacker behaviors in a matrix.
- Used for detection engineering, threat hunting, and defensive analysis.

### Common Tactics
- Initial Access.
- Execution.
- Persistence.
- Privilege Escalation.
- Defense Evasion.
- Credential Access.
- Lateral Movement.
- Command and Control.
- Exfiltration.
- Impact.

### Kill Chain vs. MITRE ATT&CK
- **Cyber Kill Chain:** High-level ordered attack stages.
- **MITRE ATT&CK:** Detailed matrix of attacker tactics and techniques without a mandatory sequence.

### TTP Terminology
- **Tactic:** Attacker's objective — WHY.
- **Technique:** Method used to achieve an objective — HOW.
- **Procedure:** Specific implementation of a technique.

**Exam:** Structured catalog of attacker behaviors and TTPs → MITRE ATT&CK.

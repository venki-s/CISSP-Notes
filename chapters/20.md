
# Chapter 20 — Software Development Security

## 1. Secure Software Development

- Integrate security throughout the SDLC (Shift Left).
- Define security requirements early and reassess them after significant changes.
- Use established authentication, authorization, and session-management mechanisms.
- Validate input on the server; client-side validation can be bypassed.
- **Limit Check:** Ensures values fall within permitted ranges.
- **Escaping/Encoding:** Prevents special characters from being interpreted as executable instructions.
- **Error Handling:** Do not disclose stack traces or sensitive internal information.
- **Security Logging:** Record authentication failures, access violations, exceptions, and administrative changes.
- **Fail-Secure:** Deny access on failure; generally preferred.
- **Fail-Open:** Permit access on failure when justified by availability or safety requirements.

---

## 2. Software Development Life Cycle (SDLC)

1. **Conceptual Definition:** Business purpose and high-level requirements.
2. **Functional Requirements:** Define inputs, behavior, and outputs.
3. **Control Specifications:** Specify security controls.
4. **Design Review:** Validate design against functional/security requirements.
5. **Coding:** Implement secure software.
6. **Code Review:** Identify defects and security weaknesses.
7. **System Testing:** Verify functionality, security, and regression behavior.
8. **User Acceptance Testing (UAT):** Users confirm business requirements.
9. **Maintenance:** Controlled changes and ongoing security support.

### Key Distinctions
- **Verification:** Does the product meet specifications?
- **Validation:** Does the product meet actual user needs?
- **Regression Testing:** Ensures changes do not break existing functionality.

## 5. Change and Configuration Management

### Change Management
1. **Request Control:** Submit and prioritize change requests.
2. **Change Control:** Develop, test, and document changes.
3. **Release Control:** Approve deployment; remove debug code/backdoors.

### Software Configuration Management (SCM)
1. **Identification:** Document configuration items.
2. **Control:** Authorize configuration changes.
3. **Status Accounting:** Track changes and versions.
4. **Audit:** Verify actual configuration matches authorized records.

### Code Repositories and Libraries
- Enforce least-privilege read/write access.
- Protect source integrity and change history.
- Never expose passwords, tokens, or API keys.
- Track third-party library vulnerabilities and updates.

## 6. Programming and Software Testing

### Programming
- **Compiler:** Translates source code into executable/intermediate code.
- **Interpreter:** Executes source/intermediate instructions through a runtime.
- **Decompiler:** Attempts to reconstruct higher-level code.
- **Disassembler:** Converts machine code into assembly.
- **Obfuscation:** Makes code harder to understand/reverse engineer.

### Object-Oriented Programming (OOP)
- **Encapsulation:** Hides internal implementation.
- **Inheritance:** Child class inherits parent characteristics.
- **Polymorphism:** Same interface supports different behavior.
- **Delegation:** Forwards a request to another object.
- **High Cohesion:** Related responsibilities within a module — desirable.
- **Low Coupling:** Minimal dependency between modules — desirable.

### Testing
- **White-Box:** Internal code/logic visible.
- **Black-Box:** Tests inputs/outputs without code knowledge.
- **Gray-Box:** Partial internal knowledge informs testing.
- **Use Case:** Expected legitimate behavior.
- **Misuse Case:** Malicious/unauthorized behavior.
- **Reasonableness Check:** Validates realistic output values.
- Independent testing reduces developer bias.

## 7. API and Third-Party Software Security

### APIs
- Authenticate and authorize API requests.
- Validate inputs and enforce access controls server-side.
- Protect API keys and secrets.
- Use encrypted communications.
- Test APIs for vulnerabilities.

### Acquired Software
- **COTS:** Commercial off-the-shelf.
- **OSS:** Open-source software.
- **SaaS:** Vendor-hosted application.

### Security Requirements
- Assess vendor security and software vulnerabilities.
- Monitor patches, dependencies, and support commitments.
- Evaluate SLAs and security responsibilities.
- Outsourcing does not remove organizational security accountability.

## 8. Database Fundamentals

### Database Models
- **Hierarchical:** Parent-child tree; one-to-many.
- **Distributed:** Logically connected databases across locations.
- **Relational:** Tables containing rows and columns.
- **Object-Oriented:** Stores objects.
- **Object-Relational:** Combines relational and object-oriented models.

### Relational Terminology

| Term | Meaning |
|---|---|
| Relation | Table |
| Tuple | Row |
| Attribute | Column |
| Cardinality | Number of rows |
| Degree | Number of columns |
| Domain | Allowed attribute values |
| Candidate Key | Minimal unique identifier |
| Primary Key | Selected candidate key |
| Alternate Key | Candidate key not selected |
| Foreign Key | References another table's key |

### Additional Concepts
- **Referential Integrity:** Prevents invalid foreign-key references.
- **Normalization:** Reduces redundancy; common forms 1NF, 2NF, 3NF.
- **DDL:** Defines or modifies database schema.
- **DML:** Retrieves or modifies database data.
- **ODBC:** Standardized interface for accessing different DBMS products.

## 9. Database Transactions — ACID

| Property | Meaning |
|---|---|
| Atomicity | Entire transaction succeeds or fails |
| Consistency | Database rules/integrity remain satisfied |
| Isolation | Concurrent transactions do not improperly interfere |
| Durability | Committed changes persist |

### Transaction Controls
- **COMMIT:** Saves transaction changes.
- **ROLLBACK:** Reverses unsuccessful/uncommitted transaction changes.

### Concurrency Problems
- **Lost Update:** One concurrent update overwrites another.
- **Dirty Read:** Reading data from an uncommitted transaction.
- Locking/concurrency controls help prevent these problems.

## 10. Database Security

### Aggregation vs. Inference
- **Aggregation:** Combining multiple low-sensitivity records to reveal higher-sensitivity information.
- **Inference:** Deducing sensitive information from nonsensitive facts.

### Security Controls
- **Views:** Restrict access to selected rows/columns.
- **Partitioning:** Separates database data into distinct security partitions.
- **Cell Suppression:** Hides individual fields/cells.
- **Content-Dependent Access:** Decisions based on data content.
- **Context-Dependent Access:** Decisions based on surrounding conditions/activity.
- **Semantic Integrity:** Enforces valid values and database constraints.
- **Noise/Perturbation:** Introduces controlled data distortion to reduce disclosure.

### Polyinstantiation
- Multiple records with identical apparent primary keys but different data at different classification levels.
- Used in multilevel security to prevent certain inference attacks.

### Database Contamination
- Mixing data with different security classification/handling requirements.

## 11. NoSQL and Storage Security

### NoSQL Models
- **Key-Value:** Key/value pairs.
- **Document:** Stores JSON/XML-like documents.
- **Graph:** Nodes and relationships (edges).

### Storage Security
- Protect filesystem and cloud storage permissions.
- Encrypt sensitive stored information.
- Prevent unauthorized access across classification levels.
- **Covert Storage Channel:** Transfers information between security levels through shared storage resources.

## 12. Knowledge-Based Systems and AI

### Expert Systems
- **Knowledge Base:** Stores expert IF/THEN rules.
- **Inference Engine:** Applies rules to derive conclusions.

### Machine Learning
- **Supervised:** Training with labeled data.
- **Unsupervised:** Finds patterns in unlabeled data.

### Neural Networks
- Interconnected computational units with weighted relationships.
- Learn patterns by adjusting weights during training.
- **Delta Rule:** Method for adjusting neural-network weights.

### Security Application
- Log analysis, anomaly detection, and identification of suspicious behavior.


# Chapter 13 — Managing Identity and Authentication

**Domain 5: Identity and Access Management (IAM)**  
**Source:** ISC2 CISSP Official Study Guide, 10th Edition  
**Coverage:** Complete supplied Chapter 13 material

> CISSP approach: Understand what a control does, how it operates, what it does NOT guarantee, and when it is the best security choice.

---

## 1. Controlling Access to Assets

### Assets Requiring Protection

- **Information:** Files, databases, records, and intellectual property.
- **Systems:** Servers and IT systems providing business functionality.
- **Devices:** Computers, routers, switches, storage, and mobile devices.
- **Facilities:** Buildings, server rooms, and other physical locations.
- **Applications:** Software providing access to organizational resources.
- **Services:** Printing, networking, support, and other organizational services.

**Important:** Organizational data stored on employee-owned devices remains an organizational asset.

### Physical vs. Logical Access Controls

- **Physical Controls:** Protect physical resources and facilities.
  - Examples: Locks, fences, guards, turnstiles, and secure server rooms.
- **Logical Controls:** Restrict access to digital resources.
  - Examples: Authentication, authorization, permissions, and access control systems.

### Access Control and CIA

- **Confidentiality:** Prevent unauthorized reading or disclosure.
- **Integrity:** Prevent or detect unauthorized modification.
- **Availability:** Ensure authorized subjects can access resources when needed.

**Exam distinction:**
- Unauthorized reading = Confidentiality violation.
- Unauthorized modification = Integrity violation.
- Authorized user unable to access data = Availability violation.

## 2. Identification, Authentication, Authorization, and Accounting

### Identification

- A subject claims an identity.
- Examples: Username, employee ID, or account identifier.
- Each subject should have a unique identity.
- Identification alone does NOT prove identity.

### Authentication

- Verifies the claimed identity using authentication factors.
- Examples: Password, smartcard, biometric, or authenticator.
- Authentication credentials must be protected.
- Passwords should be stored using secure password hashing rather than plaintext.

### Authorization

- Determines which resources and actions a subject may access.
- Based on assigned permissions and privileges.
- Follows the **Principle of Least Privilege**.
- Successful authentication does NOT imply unrestricted authorization.

### Accounting

- Records and tracks subject activities.
- Implemented using logging, monitoring, and auditing.
- Creates audit trails for accountability and investigations.
- Records typically identify WHO performed WHAT action, WHEN, and WHERE.

### AAA Model

| Function | Purpose |
|---|---|
| Authentication | Verify identity |
| Authorization | Determine permitted actions |
| Accounting | Record activities |

**Identification precedes AAA authentication.**

### Critical CISSP Distinctions

- **Identification:** Claiming an identity.
- **Authentication:** Proving the identity.
- **Authorization:** Determining what the identity can do.
- **Accounting:** Recording what the identity did.
- Accountability depends on reliable identification and authentication.
- Accountability does NOT require successful authorization.
- Failed or unauthorized access attempts can still be logged.
- Shared accounts weaken individual accountability.
- Audit logs provide evidence supporting accountability, but logs alone do not guarantee cryptographic nonrepudiation.

### Example

1. Enter username → Identification.
2. Enter password → Authentication.
3. Check permissions → Authorization.
4. Record access activity → Accounting.

**Exam trap:** A user who successfully logs in but cannot read a restricted file has passed authentication and failed authorization.

## 3. Subjects and Objects

- **Subject:** Active entity requesting access or performing operations.
  - Examples: User, process, application, service, or computer.
- **Object:** Passive entity being accessed.
  - Examples: File, database, printer, application, or storage device.

### Important Points

- Subjects request access to objects.
- An entity can act as a subject in one interaction and an object in another.
- A web application acts as an object when responding to a user request.
- The same application acts as a subject when querying a database.

**Exam rule:** Subject = Active requester; Object = Resource being accessed.

---

## 4. Identity Proofing, Registration, and Enrollment

### Identity Proofing

- Establishes that a person is associated with a claimed real-world identity.
- Uses evidence such as passports, driving licenses, and other authoritative records.
- Should occur before granting organizational identities and privileges.

### Registration

- Establishes an identity/account within an IAM system.
- May include account creation and recording identifying attributes.

### Enrollment

- Registers authentication credentials or biometric reference information.
- Examples: Registering a security key or capturing a fingerprint template.

### Knowledge-Based Authentication (KBA)

- Uses personal information to verify a claimed identity.
- May use information obtained from authoritative third-party sources.
- Historically used during identity proofing.

### Cognitive Passwords / Security Questions

- Uses previously registered answers to personal questions.
- Common in legacy password recovery systems.
- Examples: Mother's maiden name, first pet, or first car.

### KBA Security Risks

- Answers may be available through social media.
- Personal information may be guessed or stolen.
- Static security questions are discouraged by NIST.

**Exam distinctions:**
- Identity Proofing = Verify real-world identity.
- Registration = Establish account/identity.
- Enrollment = Capture authenticator information.
- Authentication = Verify identity during access.
- Static security questions are weak account-recovery mechanisms.

## 5. Authentication Factors

### Primary Authentication Factors

| Factor | Type | Examples |
|---|---|---|
| Something You Know | Type 1 | Password, PIN, passphrase |
| Something You Have | Type 2 | Smartcard, hardware token, authenticator |
| Something You Are | Type 3 | Fingerprint, iris, retina, face |

### Single-Factor Authentication

- Uses one factor category.

### Multifactor Authentication (MFA)

- Uses two or more different factor categories.
- Reduces dependence on a single authentication mechanism.

### MFA Examples

| Combination | MFA? |
|---|---|
| Password + PIN | No |
| Password + Security Question | No |
| Password + Smartcard | Yes |
| Smartcard + PIN | Yes |
| Password + Fingerprint | Yes |
| Hardware Token + Fingerprint | Yes |

**Critical:** Multiple authentication credentials are not necessarily multiple factors.

### Additional Attributes

- **Somewhere You Are:** Geographic or network location.
- **Something You Do:** Behavioral actions, gestures, or patterns.
- **Context-Aware Authentication:** Evaluates location, device, time, and other environmental signals.

### Context-Aware Authentication

- IAM evaluates additional context before granting access.
- A login from an unusual country may trigger denial or additional authentication.
- MDM systems can inspect device characteristics and policy compliance.

### Limitations

- IP-based geolocation may be inaccurate or manipulated through VPNs.
- Device characteristics can change or be spoofed.
- Contextual attributes should not be blindly trusted as identity proof.

**Exam principle:** Authentication strength depends on the quality and independence of the factors, not merely their number.

## 6. Password Security

### Password Weaknesses

- Users choose predictable passwords.
- Password reuse increases exposure.
- Passwords can be shared or phished.
- Network interception may expose poorly protected credentials.
- Stolen password databases enable offline cracking.
- Static passwords remain valid until changed or revoked.

### Password Attack Types

- **Brute Force:** Tries many possible passwords.
- **Dictionary Attack:** Uses predefined password lists.
- **Password Spraying:** Attempts common passwords across many accounts.
- **Credential Stuffing:** Reuses credentials obtained from previous breaches.

### Password vs. Passphrase

- **Password:** Secret character string used for authentication.
- **Passphrase:** Longer secret, often using multiple words.
- Passphrases can improve memorability while allowing greater length.
- Longer unpredictable passwords generally resist guessing better.

### PIN

- Numeric authentication secret.
- Classified as Something You Know.
- Often combined with smartcards or hardware authenticators.

---

## 7. Password Policy Components

### Maximum Password Age

- Determines how long a password remains valid.
- Traditional policies require changes after a specified period.

### Minimum Password Age

- Prevents immediate repeated password changes.
- Helps stop users from bypassing password history.

### Password History

- Prevents reuse of previously used passwords.
- Often combined with minimum password age.

### Password Length

- Minimum number of permitted characters.
- Longer passwords generally provide better resistance to exhaustive guessing.

### Password Complexity

- Requirements involving character categories:
  - Uppercase letters.
  - Lowercase letters.
  - Numbers.
  - Special characters.

### CISSP Scenario

A user repeatedly changes their password until they can reuse the original password.

**Best controls:** Password history combined with minimum password age.

**Exam distinctions:**
- Maximum Age = Forces expiration.
- Minimum Age = Prevents rapid changes.
- History = Prevents reuse.
- Length = Number of characters.
- Complexity = Character categories.

## 8. NIST and PCI DSS Password Guidance

### NIST SP 800-63B — Study Guide Summary

- Passwords must not be stored in plaintext.
- Use secure password hashing.
- Avoid arbitrary periodic password expiration.
- Require changes when compromise is suspected or confirmed.
- Avoid mandatory special-character composition rules.
- Allow long passphrases and spaces.
- Permit copy-and-paste for password managers.
- Screen passwords against common or compromised password lists.
- Encourage strong, unique passwords.

### NIST Reasoning

- Forced password expiration can encourage predictable password modifications.
- Complex composition rules may lead to insecure workarounds.
- Password managers support unique, unpredictable credentials.
- Longer passwords improve resistance to guessing attacks.

### Password Length

- The supplied study-guide text describes an 8-character minimum and support for passwords up to 64 characters.
- These are textbook-era figures, not a substitute for current NIST requirements.

### PCI DSS Version 4.0 — Study Guide Summary

The supplied text describes:

- Minimum password length requirements.
- Alphabetic and numeric character requirements.
- Password history restrictions.
- Password expiration provisions.

### NIST vs. PCI DSS

- **NIST:** General digital identity and authentication guidance.
- **PCI DSS:** Mandatory security requirements for applicable payment-card environments.
- Compliance obligations can impose controls beyond general recommendations.

**Exam principle:** Apply the requirements of the governing standard when compliance is mandatory.

**Standards caution:** The textbook simplifies password expiration and length requirements. Specific NIST and PCI DSS provisions depend on version, authentication method, and scope; use the current official standards for implementation.

## 9. Something You Have — Smartcards and Authenticators

### Smartcards

- Physical cards containing integrated circuits.
- May contain certificates and cryptographic keys.
- Support identification and authentication.
- Often combined with a PIN or password.
- Can support asymmetric cryptography and digital signatures.
- Possession alone does not prove the holder is the legitimate owner.

**Exam distinction:**
- Smartcard = Something You Have.
- PIN = Something You Know.
- Smartcard + PIN = MFA.

### Authentication Tokens

- Hardware or software mechanisms that generate authentication codes.
- Frequently provide one-time passwords (OTPs).
- Often combined with passwords for MFA.

### TOTP — Time-Based One-Time Password

- Generates OTPs based on time.
- Requires synchronized time between authenticator and verification server.
- Codes change at configured intervals.
- Described as a synchronous authenticator.

### HOTP — HMAC-Based One-Time Password

- Generates OTPs using HMAC and an incrementing counter.
- Does not require clock synchronization.
- Counter must remain synchronized with the verification system.
- Described as an asynchronous authenticator.

### TOTP vs. HOTP

| TOTP | HOTP |
|---|---|
| Time-based | Counter-based |
| Requires clock synchronization | Requires counter synchronization |
| Changes periodically | Changes when counter advances |
| Synchronous | Asynchronous |

### Authenticator Risks

- Device theft or loss.
- Hardware failure or battery depletion.
- Recovery processes may become attack targets.
- OTPs can be phished or intercepted in real time.

**Exam priority:** TOTP = Time; HOTP = Counter.

## 10. Something You Are — Biometrics

### Biometric Authentication

- Uses measurable physiological or behavioral characteristics.
- Supports identification, authentication, or both.
- Does NOT itself determine authorization.
- Requires secure enrollment and protected reference templates.

### Biometric Identification

- **1:N Matching.**
- Compares a biometric sample against multiple stored identities.
- Determines which enrolled identity may match.

### Biometric Authentication / Verification

- **1:1 Matching.**
- Compares a biometric sample against a template for the claimed identity.
- Determines whether the subject matches the claim.

**Exam distinction:** Identification = 1:N; Authentication = 1:1.

### Biometric Methods

#### Fingerprints
- Use ridge patterns and minutiae.
- Common for access control and endpoint authentication.

#### Facial Recognition
- Uses facial geometry and patterns.
- Can support identification and verification.

#### Retina Scans
- Examine blood-vessel patterns at the back of the eye.
- Described as extremely accurate in the study guide.
- More intrusive than some alternatives.
- May raise privacy and medical-information concerns.

#### Iris Scans
- Examine the colored area surrounding the pupil.
- Highly accurate and generally less intrusive than retina scans.
- Accuracy may depend on scanning conditions.

#### Palm Scans
- Use palm characteristics or vein patterns.
- Can support secure identification and authentication.

#### Voice Pattern Recognition
- Examines characteristics of a person's voice.
- Can be affected by environmental or physical changes.

### Voice vs. Speech Recognition

- **Voice Recognition:** Identifies WHO is speaking.
- **Speech Recognition:** Identifies WHAT words are spoken.

### Biometric Risks

- Spoofing using copied biometric characteristics.
- Privacy concerns.
- False acceptances and false rejections.
- Inconvenience or user resistance.
- Difficulty replacing compromised biometric characteristics.

## 11. Biometric Error Rates

### False Rejection Rate (FRR)

- Legitimate user incorrectly rejected.
- False Negative.
- **Type I Error** in the study guide.
- Primarily affects availability and usability.

### False Acceptance Rate (FAR)

- Unauthorized user incorrectly accepted.
- False Positive.
- **Type II Error** in the study guide.
- Primarily affects security.

### Crossover Error Rate (CER)

- Also called Equal Error Rate (EER).
- Point where FAR and FRR are equal.
- Used to compare biometric system accuracy.
- **Lower CER/EER = Better overall accuracy.**

### Biometric Error Comparison

| Metric | Meaning |
|---|---|
| FRR | Legitimate person rejected |
| FAR | Unauthorized person accepted |
| CER/EER | FAR equals FRR |

### Sensitivity Trade-off

#### Strict Matching Threshold
- Lower FAR.
- Higher FRR.
- Better protection against unauthorized access.
- More legitimate users may be rejected.

#### Permissive Matching Threshold
- Higher FAR.
- Lower FRR.
- Better convenience.
- Higher unauthorized acceptance risk.

### CISSP Scenario

A secure facility wants to minimize unauthorized access, even if legitimate users occasionally require multiple attempts.

**Best choice:** Stricter matching threshold to reduce FAR.

**Important:** The operating threshold does not necessarily need to equal the CER/EER point.

## 12. Biometric Enrollment and Performance

### Enrollment

- Captures the user's biometric characteristic.
- Creates a stored reference profile/template.
- Required before subsequent authentication.

### Enrollment Time

- Time required to register biometric information.
- Longer enrollment times reduce convenience and acceptance.
- The study guide considers enrollment exceeding approximately two minutes undesirable.

### Throughput Rate

- Time required to scan and approve or reject an individual.
- Important where many people must authenticate.
- The study guide describes approximately six seconds or less as generally acceptable.

### User Acceptance

- Willingness to use the biometric mechanism.
- Influenced by privacy, convenience, accuracy, and intrusiveness.

**Exam distinctions:**
- Enrollment Time = Initial registration.
- Throughput Rate = Subsequent verification time.
- FRR = Legitimate user rejected.
- FAR = Unauthorized user accepted.
- CER = Biometric accuracy comparison.

## 13. MFA, SMS Authentication, and Passwordless Authentication

### Multifactor Authentication

- Uses two or more independent authentication factor categories.
- Helps resist attacks that compromise only one factor.

### SMS-Based OTP

- Commonly used as an additional authentication mechanism.
- Better than password-only authentication in many circumstances.
- Weaker than phishing-resistant authentication methods.

### SMS Risks

- SIM swapping.
- Mobile carrier account compromise.
- Interception or redirection of text messages.
- OTPs displayed on unlocked or insufficiently protected devices.
- Real-time phishing.

**Exam distinction:** SMS OTP is a possession-associated mechanism but has significant weaknesses and is not phishing-resistant.

### Passwordless Authentication

- Allows authentication without entering a memorized password.
- Can use biometrics, cryptographic keys, security keys, or platform authenticators.
- Reduces dependency on static passwords.

### FIDO — Fast Identity Online

- Industry initiative supporting passwordless and stronger authentication.
- Uses cryptographic authentication mechanisms.
- Hardware security keys are examples of supported authenticators.
- Helps reduce password-related risks.

### Passkeys

- Cryptographic credentials associated with an application or website.
- Can support passwordless authentication.
- May use device biometrics or local PINs to unlock the authenticator.
- The local biometric is not necessarily transmitted to the remote service.

**CISSP distinction:** Passwordless authentication is not automatically MFA. The assurance depends on the authenticator design and factors used.

## 14. Device Authentication

### Purpose

- Verifies the identity of computers and other endpoints.
- Prevents unauthorized devices from accessing organizational resources.
- Complements user authentication.

### Domain Computer Accounts

- Domain-joined computers can possess machine identities and credentials.
- Computer credentials help establish trust with centralized systems.
- Device authentication can fail when machine credentials are invalid or unsynchronized.

### Device Fingerprinting

- Identifies devices using a collection of characteristics.
- Examples:
  - Operating system and version.
  - Browser configuration.
  - Screen resolution.
  - Time zone.
  - HTTP headers.
  - Browser settings and characteristics.

### Device Fingerprinting Limitations

- Characteristics can change over time.
- Some attributes can be spoofed.
- Fingerprinting should be supplemented with stronger controls.

### MDM — Mobile Device Management

- Enforces device configuration and security policies.
- Can inspect device characteristics and compliance.

### NAC — Network Access Control

- Evaluates endpoint identity and security posture.
- Allows, restricts, or denies network connectivity.
- Can quarantine noncompliant endpoints.

### IEEE 802.1X

- Provides port-based network access control.
- Used in wired and wireless networks.
- Requires successful authentication before network admission.

**Exam distinctions:**
- Device Fingerprinting = Recognition using device characteristics.
- Device Authentication = Verification of device identity.
- MDM = Device management and policy enforcement.
- NAC = Network admission and posture enforcement.
- 802.1X = Port-based authentication framework.

## 15. Service Authentication and Service Accounts

### Service Account

- Identity used by an application or service rather than an individual.
- Can access files, databases, systems, or other services.
- May require elevated privileges for specific operations.

### Service Account Risks

- Excessive permissions.
- Hardcoded or exposed credentials.
- Weak or default passwords.
- Long-lived credentials.
- Interactive logon capability.
- Lack of monitoring or ownership.
- Unauthorized reuse across applications.

### Service Account Security Controls

- Apply Least Privilege.
- Use dedicated service identities.
- Restrict interactive login where unnecessary.
- Use strong authentication mechanisms.
- Securely store service credentials.
- Rotate credentials through controlled processes.
- Periodically review permissions.
- Disable unnecessary or unused service accounts.
- Prefer managed identities or certificate-based authentication where appropriate.

### Password Expiration Consideration

- Services cannot necessarily respond to interactive password-expiration prompts.
- Uncoordinated credential changes can disrupt availability.
- The study guide discusses nonexpiring service passwords as an operational workaround.
- Better security requires controlled rotation and secure credential management.

**Exam scenario:** A service stops functioning after its password expires.

**Cause:** The service cannot update its credential interactively.

**Improvement:** Implement managed credential rotation and application-safe credential updates.

### Privileged Built-In Accounts

- Built-in administrator or service accounts may possess extensive privileges.
- Default or weak credentials can create serious risks.
- Disable unnecessary accounts and restrict powerful built-in identities.

## 16. Mutual Authentication

### Definition

- Both communicating entities authenticate each other.
- Commonly uses digital certificates.

### Example

A remote employee connects to a corporate VPN.

1. The client verifies the VPN server.
2. The VPN server verifies the client.
3. Communication proceeds only after required checks succeed.

### Security Benefits

- Helps prevent connections to rogue servers.
- Reduces impersonation risks.
- Strengthens trust between communicating endpoints.

### Important Distinction

- **One-Way Authentication:** One endpoint authenticates the other.
- **Mutual Authentication:** Both endpoints authenticate each other.

**Exam scenario:** A user is redirected to a malicious server pretending to be the legitimate VPN server.

**Protection:** Proper server authentication and mutual authentication where required.

## 17. Centralized vs. Decentralized Identity Management

### Centralized Access Control

- A central authority manages authorization decisions or identity policies.
- Administrative changes are managed from a central location.
- Supports consistent policy enforcement.
- Often simplifies management and auditing.

#### Advantages
- Lower administrative overhead.
- Easier access management.
- Consistent security policies.
- Better centralized visibility.

#### Disadvantages
- Potential single point of failure.
- High-value compromise target.
- Requires resilience and availability planning.

### Decentralized / Distributed Access Control

- Multiple systems or administrators manage access decisions.
- Can offer local independence.

#### Advantages
- Greater local autonomy.
- Reduced reliance on one central decision point.

#### Disadvantages
- Higher administrative overhead.
- Inconsistent policy enforcement.
- Harder access reviews and auditing.
- Permissions may become inconsistent.

### Comparison

| Centralized | Decentralized |
|---|---|
| Central authority | Multiple authorities |
| Easier administration | More administrative effort |
| Consistent policies | Risk of inconsistency |
| Potential central failure | Distributed management complexity |

**Exam principle:** Centralized IAM improves consistency but requires resilient infrastructure.

## 18. Single Sign-On (SSO)

### SSO

- Allows users to authenticate once and access multiple authorized resources.
- Reduces repeated authentication.
- Improves convenience.
- Can reduce password-management burden.

### Advantages

- Fewer repeated login prompts.
- Improved user experience.
- Centralized authentication management.
- Simplified account administration.
- Easier enforcement of authentication policies.

### Disadvantages

- Compromised SSO credentials may expose multiple resources.
- The identity provider becomes a critical dependency.
- Incorrect trust configurations can have broad impact.
- Authentication compromise may affect multiple applications.

### Security Controls

- MFA.
- Strong identity-provider security.
- Session management.
- Monitoring and logging.
- Least privilege.
- Resilient authentication infrastructure.

**Exam distinction:** SSO reduces repeated authentication; it does NOT mean users automatically receive authorization to every connected application.

## 19. LDAP, Directory Services, Domains, and Trusts

### Directory Service

- Centralized repository containing identity and resource information.
- May store users, groups, computers, and other directory objects.

### LDAP — Lightweight Directory Access Protocol

- Protocol for accessing and querying directory services.
- Commonly associated with centralized identity infrastructure.
- Used by systems such as Active Directory.

### LDAP Security

- Directory information is subject to access controls.
- Authentication and authorization govern permitted operations.
- Secure LDAP connections using TLS where appropriate.

### Security Domain

- Collection of subjects and objects under a common security policy.

### Domain Trust

- Establishes a trust relationship between security domains.
- Allows identity information or authentication to be recognized across domains.
- Does not automatically grant access to every resource.

### Trust Direction

- **One-Way Trust:** Trust relationship operates in one direction.
- **Two-Way Trust:** Both domains establish trust relationships.

### LDAP and PKI

- LDAP directories may assist certificate-related lookups.
- PKI manages digital certificates and their lifecycle.

**Exam distinctions:**
- LDAP = Directory access protocol.
- Directory Service = Identity/resource information repository.
- Trust = Recognition relationship between security domains.
- SSO = Authentication experience across resources.

**Important:** LDAP does not itself constitute a complete SSO or federation solution.

## 20. Federated Identity Management (FIM)

### Definition

- Links identities across multiple systems or organizations.
- Allows users to access trusted external resources using their existing identity.
- Extends identity management beyond one security domain.

### Federation Operation

1. User authenticates with their home organization.
2. A trusted identity system confirms authentication.
3. The external service accepts the trusted identity information.
4. The external service applies its own access policies.

### Federation Benefits

- Reduces separate account/password management.
- Supports cross-organizational collaboration.
- Improves user experience.
- Allows centralized identity administration.

### Federation Risks

- Identity-provider compromise affects multiple relying services.
- Misconfigured trust can grant inappropriate access.
- Federation depends on secure identity assertions.
- Access revocation must propagate appropriately.

### Identity Provider and Service Provider

- **Identity Provider (IdP):** Authenticates users and provides trusted identity information.
- **Service Provider (SP):** Provides resources using trusted identity information and its own authorization rules.

### Important Distinction

- Federation establishes identity trust.
- Federation does NOT automatically authorize access to every resource.
- Each participating organization controls permitted resource access.

---

## 21. Federation Standards

### SAML — Security Assertion Markup Language

- XML-based framework for exchanging authentication and authorization information.
- Widely associated with enterprise federated SSO.
- Uses assertions exchanged between trusted parties.

### OAuth

- Framework for delegated authorization.
- Allows applications to obtain limited access to resources.
- OAuth alone is NOT an authentication protocol.

### OpenID Connect (OIDC)

- Identity layer built on OAuth 2.0.
- Supports authentication and identity information exchange.
- Commonly used for modern web and mobile login flows.

### CISSP Comparison

| Technology | Main Purpose |
|---|---|
| LDAP | Directory access |
| SAML | Federation and authentication assertions |
| OAuth | Delegated authorization |
| OIDC | Authentication and identity layer |
| SSO | One login experience across resources |
| FIM | Trusted identity relationships across systems |

**Critical exam distinction:** OAuth = Authorization; OIDC = Authentication built on OAuth.

---

## 22. Federation Deployment Models

### Cloud-Based Federation

- Federation infrastructure or identity services are hosted in the cloud.
- Common for access to SaaS applications.
- May involve external identity providers.

### On-Premises Federation

- Federation components are hosted within organizational infrastructure.
- Provides greater direct control over infrastructure.
- Requires internal maintenance and administration.

### Hybrid Federation

- Combines on-premises and cloud-based identity infrastructure.
- Supports access across internal systems and cloud services.

### Comparison

| Model | Primary Characteristic |
|---|---|
| On-Premises | Greater internal infrastructure control |
| Cloud | Provider-hosted identity services |
| Hybrid | Integration of cloud and internal identity systems |

**Exam principle:** Select the federation model according to business requirements, control, cost, availability, and risk.

## 23. Just-in-Time (JIT) Provisioning

### Definition

- Automatically creates a user account when the user first accesses a trusted application.
- Avoids advance manual account creation.
- Often works with federated identity systems.

### Operation

1. User authenticates with the home identity provider.
2. User accesses an external service for the first time.
3. Identity information is exchanged.
4. The external service creates the user account.
5. The user receives the permitted access.

### Benefits

- Reduces administrative effort.
- Supports onboarding at scale.
- Avoids unnecessary precreated accounts.
- Improves provisioning consistency.

### Security Considerations

- Trust configuration must be secure.
- Identity attributes must be validated.
- Provisioned privileges must follow least privilege.
- Account revocation and lifecycle management remain necessary.

**Exam distinction:** JIT provisioning creates an account when needed; it does not automatically provide unlimited privileges.

**Important:** JIT account provisioning is different from JIT privileged access, which grants elevated access only when necessary.

## 24. Credential Management Systems

### Credential Management

- Stores and manages authentication credentials.
- Reduces the need to memorize multiple passwords.
- May support automated login or credential retrieval.

### Browser Credential Managers

- Can store credentials for websites.
- Can offer automatic authentication on later visits.
- May support APIs for credential selection and sign-in.

### Password Vaults

- Store credentials in an encrypted repository.
- Typically protected by a master password or other authentication.
- Support unique passwords for different services.

### Password Vault Risks

- Weak master password.
- Compromised or unlocked vault.
- Inadequate backup and recovery.
- Unauthorized credential export.
- Centralized exposure if the vault is compromised.

### Security Controls

- Strong master authentication.
- MFA where available.
- Encryption.
- Access restrictions.
- Monitoring and auditing.
- Secure recovery procedures.

### IDaaS — Identity as a Service

- Cloud-delivered IAM capabilities.
- Can provide authentication, SSO, and identity integration for SaaS applications.
- Reduces the need to host every IAM component internally.

### IDaaS Risks

- Dependence on the external provider.
- Provider availability and security.
- Misconfigured federation.
- Compliance and data-handling concerns.

**Exam distinctions:**
- Password Vault = Secure credential storage.
- IDaaS = Cloud-hosted identity management services.
- SSO = Single authentication experience.
- Federation = Trust relationships between identity environments.

## 25. Scripted Access

### Scripted Access / Logon Scripts

- Automates login procedures for multiple systems.
- Can simulate an SSO experience.
- Each target system may still perform separate authentication.

### Security Risks

- Credentials may be embedded in scripts.
- Scripts may contain plaintext passwords.
- Unauthorized script access can expose privileged credentials.

### Controls

- Restrict script access.
- Avoid hardcoded credentials.
- Use secure secret storage.
- Protect credentials during transmission.
- Prefer proper SSO or identity federation when available.

**Exam distinction:** Scripted access can imitate SSO but is not necessarily true centralized authentication.

---

## 26. Session Management

### Purpose

- Protects authenticated sessions from unauthorized reuse or hijacking.
- Ensures authentication does not grant indefinite unattended access.

### Session Security Controls

- Secure session identifiers.
- Session expiration.
- Inactivity timeouts.
- Reauthentication for sensitive activities.
- Secure logout.
- TLS protection.
- Protection against session hijacking.

### Desktop Session Locking

- Automatically locks a workstation after inactivity.
- Requires authentication to resume access.
- Protects unattended systems.

### Web Application Session Management

- Applications create session identifiers following authentication.
- Session identifiers associate requests with authenticated sessions.
- Tokens may be transmitted through cookies or other mechanisms.
- TLS helps protect session information during transmission.

### Session Timeout Types

- **Idle Timeout:** Ends sessions after inactivity.
- **Absolute Timeout:** Ends sessions after a maximum lifetime, regardless of activity.

### Session Timeout Considerations

- High-value applications generally need shorter inactivity periods.
- Low-risk applications may tolerate longer periods.
- Timeout values should be based on risk and usability.

### Study Guide Examples

- High-value applications: Approximately 2–5 minutes.
- Lower-value applications: Approximately 15–30 minutes.

These are examples, not universal mandatory settings.

### Important Risks

- Closing a browser tab does not necessarily terminate a server session.
- Stolen session identifiers may enable session hijacking.
- Long-lived sessions increase exposure on unattended devices.

**Exam principle:** Authentication establishes a session; secure session management controls how that session is maintained and terminated.

## 27. Identity and Access Provisioning Lifecycle

### IAM Lifecycle

- Creation.
- Provisioning.
- Maintenance.
- Access review.
- Role transition.
- Deprovisioning.
- Deletion/retirement.

### Joiner–Mover–Leaver (JML)

- **Joiner:** New employee joins the organization.
- **Mover:** Existing employee changes role or department.
- **Leaver:** Employee leaves the organization.

### IAM Lifecycle Goals

- Provide access when required.
- Grant only appropriate privileges.
- Update access when responsibilities change.
- Remove unnecessary access.
- Maintain accountability throughout the account lifecycle.

**Exam principle:** Identity management is a continuous process, not merely account creation.

---

## 28. Provisioning and Onboarding

### Provisioning

- Creates accounts and assigns required privileges.
- Must follow authorized organizational procedures.
- Should not be performed based on informal or unapproved requests.

### Identity Verification

- Confirm identity before creating the account.
- Use appropriate identity proofing methods.

### Account Creation

- Assign a unique username or identifier.
- Record required user attributes.
- Assign appropriate groups or roles.
- Configure authentication mechanisms.

### Automated Provisioning

- Uses predefined rules to create accounts consistently.
- Can assign groups and permissions based on department or job role.
- Reduces administrative errors.
- Supports scalability.

### Group and Role Assignment

- Groups simplify permission management.
- Roles represent job functions or responsibilities.
- Users receive permissions appropriate to assigned groups or roles.

### Onboarding Activities

- Provide required equipment.
- Configure authentication and MFA.
- Explain acceptable-use policies.
- Provide security awareness training.
- Explain device-management requirements.
- Verify the user can access required systems.

**Exam principle:** Account provisioning should follow approved workflows and the Principle of Least Privilege.

---

## 29. Deprovisioning and Offboarding

### Deprovisioning

- Removes or disables identity access when no longer required.
- Applies to employee departure, termination, and changes in responsibilities.

### Important Security Actions

- Disable or revoke access promptly.
- Terminate active sessions.
- Revoke authentication tokens and credentials where required.
- Remove group and role memberships.
- Revoke access to cloud and third-party systems.
- Recover organizational devices and authenticators.
- Transfer required business data through approved processes.
- Retain records according to policy.

### Disable vs. Delete

#### Disable Account

- Stops ordinary access while preserving account-related information.
- Supports investigation, retention, and controlled data recovery.

#### Delete Account

- Removes the account identity from the system.
- May affect ownership, encrypted data, or recovery processes.
- Should follow approved retention and handover procedures.

### Important Risk

- A terminated employee retaining access can cause sabotage or data theft.
- Dormant former-employee accounts can be misused.
- Shared credentials and service access may remain active after normal account removal.

### Encrypted Data Consideration

- Deleting an account prematurely can cause loss of access to encrypted information.
- Recovery and ownership transfer should be managed before deletion.
- Prefer controlled administrative delegation or recovery mechanisms rather than sharing former employees' credentials.

**Exam principle:** Immediately remove unauthorized access while preserving necessary business records and recovery capability.

---

## 30. Role Definition and Transition

### Role Definition

- Defines duties and the privileges required to perform them.
- Supports role-based provisioning and access management.

### Role Transition

- Occurs when employees change departments or responsibilities.
- New access must be assigned.
- Obsolete access must be revoked.

### Security Risks

- Retaining old privileges.
- Receiving unnecessary new privileges.
- Conflicting permissions.
- Unauthorized access to unrelated departments.

### Example

An employee moves from Accounting to Sales.

- Grant required Sales privileges.
- Revoke unnecessary Accounting privileges.
- Review access to shared systems.

**Exam principle:** A role change requires reviewing both newly required and previously granted access.

---

## 31. Account Maintenance and Access Reviews

### Account Maintenance

- Ongoing management of identities and permissions.
- Includes updating account information, privileges, and status.

### Account Access Review

- Periodically verifies accounts have appropriate privileges.
- Identifies unnecessary, dormant, or unauthorized accounts.
- Includes:
  - User accounts.
  - Privileged accounts.
  - Computer/system accounts.
  - Service accounts.

### Privileged Account Review

- Focuses on accounts with elevated permissions.
- Examples:
  - Administrator.
  - Root.
  - Service accounts with elevated permissions.
  - Other privileged identities.

### Inactive Account Detection

- Identify accounts unused for a defined period.
- Disable or investigate according to policy.
- The study guide gives 30 days as an example, not a universal standard.

### Excessive Privilege

- User possesses more permissions than required for assigned work.
- Violates Least Privilege.

### Privilege Creep

- User gradually accumulates permissions as job responsibilities change.
- Old privileges remain after new ones are assigned.
- Common during transfers or promotions.

### Excessive Privilege vs. Privilege Creep

| Excessive Privilege | Privilege Creep |
|---|---|
| Current permissions exceed requirements | Permissions accumulate over time |
| Can occur immediately | Often occurs after role changes |
| Violates least privilege | Leads to excessive privileges |

### Controls

- Periodic access reviews.
- Role-based provisioning.
- Approval workflows.
- Privileged account monitoring.
- Removal of unused permissions.
- Automated detection of inactive accounts.

**Exam distinction:** Privilege creep describes how excessive privilege accumulates over time.

---

## 32. Service Account Lifecycle Management

### Service Account Governance

- Maintain an inventory of service accounts.
- Assign accountable ownership.
- Document business purpose.
- Restrict privileges to required functionality.
- Review permissions regularly.
- Identify unused service identities.
- Remove accounts when services are retired.

### Service Account Risks

- Shared credentials.
- Forgotten credentials.
- Excessive privileges.
- Weak monitoring.
- Password expiration causing service failures.
- Applications running with local system or administrator permissions unnecessarily.

### Local System Account Risks

- Some services operate using highly privileged built-in system identities.
- Excessive permissions increase impact if the application is compromised.

### Best Security Choices

- Dedicated service identity.
- Least privilege.
- Managed secrets.
- Credential rotation.
- Noninteractive access restrictions.
- Review and monitoring.
- Controlled deprovisioning.

**Exam principle:** Service accounts require the same lifecycle governance as human accounts, with additional attention to unattended authentication and availability.

## 34. Scenario-Based CISSP Questions

### Scenario 1 — Authentication vs. Authorization

A user logs in successfully but cannot delete a protected file.

**Explanation:** Authentication succeeded; authorization denied deletion.

### Scenario 2 — Accountability

A user attempts to access an unauthorized resource, and the event is logged.

**Explanation:** Accounting operates even when authorization fails.

### Scenario 3 — MFA

A user provides a password and a security question.

**Explanation:** Both are knowledge factors, so this is not MFA.

### Scenario 4 — TOTP

Users cannot authenticate because their authenticator clocks differ from the server.

**Explanation:** TOTP relies on time synchronization.

### Scenario 5 — Biometric Security

A secure facility wants to minimize unauthorized acceptance.

**Explanation:** Use a stricter biometric matching threshold to lower FAR.

### Scenario 6 — Device Authentication

An organization wants to allow only compliant employee devices onto its network.

**Explanation:** Use NAC with appropriate device authentication and posture evaluation.

### Scenario 7 — Mutual Authentication

A client connects to a forged VPN server.

**Explanation:** Proper server verification and mutual authentication help prevent rogue endpoint impersonation.

### Scenario 8 — Centralized IAM

An organization wants consistent policy enforcement but is concerned about a single IAM failure.

**Explanation:** Centralized IAM simplifies management but requires resilient, highly available identity infrastructure.

### Scenario 9 — Federation

A user authenticates with their employer and accesses an external training website without another login.

**Explanation:** Federated identity with SSO.

### Scenario 10 — JIT Provisioning

A SaaS account is automatically created when a federated user first accesses the application.

**Explanation:** Just-in-Time provisioning.

### Scenario 11 — Scripted Access

A login script automatically supplies stored passwords to several systems.

**Explanation:** It simulates SSO but may expose credentials and still involve separate authentications.

### Scenario 12 — Session Management

A banking application remains authenticated after the user leaves the computer.

**Explanation:** Inactivity timeouts and session expiration reduce unauthorized reuse.

### Scenario 13 — Offboarding

A terminated employee retains access to corporate SaaS applications.

**Explanation:** Incomplete deprovisioning and federation/session revocation.

### Scenario 14 — Privilege Creep

A transferred employee retains access to the previous department.

**Explanation:** Privilege creep; remove unnecessary prior permissions.

### Scenario 15 — Service Account

An application stops working because a service account's password expired.

**Explanation:** Service identities require controlled credential rotation and availability-aware management.

## 35. CISSP Exam Traps

- Identification does NOT prove identity.
- Authentication does NOT grant authorization.
- Accounting can record denied access attempts.
- Shared accounts weaken individual accountability.
- Password + PIN is NOT MFA.
- Smartcard + PIN IS MFA.
- Biometrics can authenticate but do NOT authorize.
- Biometric identification = 1:N.
- Biometric authentication = 1:1.
- FRR = False rejection = Type I.
- FAR = False acceptance = Type II.
- Lower CER/EER = Better accuracy.
- Stricter biometric matching lowers FAR but raises FRR.
- TOTP requires time synchronization.
- HOTP requires counter synchronization.
- SMS-based OTP is vulnerable to interception and SIM swapping.
- Passwordless does NOT automatically mean MFA.
- Device fingerprinting is not equivalent to strong cryptographic device identity.
- Authentication of a server alone is not mutual authentication.
- Centralized IAM can introduce a critical availability dependency.
- SSO does not grant access to every resource.
- LDAP is a directory protocol, not an SSO standard.
- OAuth is primarily delegated authorization.
- OIDC adds authentication functionality.
- Federation establishes identity trust, not unrestricted resource access.
- JIT provisioning creates accounts when first needed.
- Credential vault compromise can expose many stored credentials.
- Closing a browser tab does not guarantee session termination.
- Account disabling and account deletion are different.
- Offboarding must include third-party and cloud access.
- Privilege creep occurs through accumulation of access over time.
- Service accounts need least privilege, ownership, and monitoring.

## 1. Shared Responsibility

1. AIS (Automated Indicator Sharing): Automatically shares cyberthreat information between the U.S. government and private organizations.  
2. Observable: Evidence of an event, such as a malicious file hash or IP address. 
3. Indicator (IoC): Observable information suggesting a possible security threat.  
4. STIX: Standard format for describing and sharing cyberthreat intelligence.  
5. TAXII: Protocol for automatically exchanging cyberthreat intelligence. 
6. Organizations are responsible to their stakeholders for making good security decisions to sustain the organization. 
7. As we become aware of new vulnerabilities and threats, we should consider it our responsibility (if not our duty) to responsibly disclose that information to the proper vendor or to an information sharing center. 

## 2. Data Localization and Data Sovereignty.  

1. Data Localization = Where data is stored. Requires data to be stored or processed within a specific country's borders. 
2. Data Sovereignty = Which country's laws apply. Data is subject to the laws and regulations of the country having jurisdiction over it, regardless of storage location.


| Feature | Data Localization | Data Sovereignty |
|---|---|---|
| Focus | Physical location | Legal jurisdiction and control |
| Requirement | Store data within specified borders | Comply with applicable local laws |
| Impact | May require local data centers | Requires legal compliance and data governance |

3. Data portability refers to the ability of individuals to easily and securely move their personal data from one system, service, or application to another.  

## 3. System

### 3.1 Processor. 

1. Computer architecture - Engineering discipline related to design and construction of computer systems at a logical level.  
2. Processor - Central Processing Unit (CPU). The chip that governs all major operations and either performs or coordinates calculations that allow a computer to perform its tasks.  
3. Execution types:  
   a. Multitasking - Handling two or more tasks simultaneously. 
   b. Multicore - A single microprocessor chip that contains independent execution cores. 
   c. Multiprocessing - A computing system with more than one CPU uses the power of more than one processor to complete a multithreaded operation. 
   d. Massively parallel processing - MPP. Hundreds or more processors with their own OS and resources, coordinated by software to perform in unity. 
   e. Multiprogramming - Similar to multitasking.  
   f. Multithreading - Multiple concurrent tasks are performed within a single process - multitasking involves multiple processes.  
4. Processing types:
5. Protection rings - Organize code and components in an OS into concentric rings.  
   a. Deep inside ring is 0, highest level of privilege and can access anything.  
   b. Kernel - Part of the OS that remains resident in memory so it can be run on demand at any time. Lives in ring 0.  
   c. Ring 1 houses the rest of the OS.  
   d. Ring 2 is somewhat privileged, I/O drivers and other system utilities reside. 
   e. Applications and programs live in Ring 3.  
6. Process states - Aka operating states. 
   a. Supervisor state - privileged, all access.  
   b. Problem state - Associated with user mode where privileges are low and access requests must be checked. 
   c. Ready - Process is ready to resume or start processing as soon as it is scheduled.  
   d. Waiting - Process is waiting for a resource, waiting for continued execution but a device or access request is to be serviced first.  
   e. Running - Executing on the CPU and goes until it finishes or it’s time slice expires or it is blocked. 
   f. Supervisory - When the process must perform an action that requires privileges that are greater than the problem state’s set of privileges.  
   g. Stopped - When a process finishes or errors out, it becomes “stopped” so the OS can recover memory and other resources.  

### 3.2 Memory.   

1. Read-Only memory - ROM. Memory the PC can read but cannot change.  
2. Programmable Read-Only memory - PROM. Similar to a ROM chip but can be programmed separately from manufacturing, but only once.  
3. Erasable Programmable Read-Only memory - EPROM. Ultraviolet EPROMs can be erased with a light. 
4. Electronically Erasable Programmable Read-Only memory - EEPROM. Electronically erasable PROM. 
5. Flash memory - Derivative from EEPROM, can be electronically erased and rewritten, can be erased in blocks or pages. 
6. Random Access Memory - RAM. Readable and writable memory that contains information a computer uses during processing.  
7. Real memory - The largest RAM storage resource available, made of dynamic RAM chips.  
8. Cache RAM - Caches that improve performance by taking data from slower devices and storing it temporarily in faster devices when repeated use is likely. 
9. Registers - Limited onboard memory in a CPU. 
10. Dynamic RAM is cheaper than static RAM because capacitors are cheaper than flip-flops. However, static RAM runs much faster than dynamic RAM.

#### 3.3 Memory Addressing.  

1. Registers The CPU also includes a limited amount of onboard memory, known as registers, that provide it with directly accessible memory locations.  
2. Immediate Addressing Immediate addressing is not a memory addressing scheme per se but rather a way of referring to data that is supplied to the CPU as part of an instruction. 
3. Direct addressing - CPU is provided with an actual address of the memory location to access
4. Indirect addressing - Similar to direct, however the address supplied doesn’t contain the actual value, it contains another memory address
5. Base+Offset Addressing Base+offset addressing uses a value stored in one of the CPU's registers or pointers as the base location to begin counting. The CPU then adds the offset supplied with the instruction to that base address and retrieves the operand from that computed memory location.   

### 3.3 Storage.  

1. Data storage devices - Used to store information that may be used any time after it’s written
2. Primary vs secondary - Primary storage is RAM. Secondary is long-term storage like hard drives.
3. Volatile vs non-volatile - Volatile devices lose their data when they lose power
4. Random vs sequential - Random access storage allow an OS to read immediately from any point. Sequential storage doesn’t.
5. Storage media security
   a. Data remanence - Data may remain on devices after it is erased
   b. SSDs can only be sanitized by destroying them
   c. Prone to theft, important to use full disk encryption

### 3.4 Input and Output Devices.  

1. Monitors - Primary concern is shoulder surfing - looking over the shoulder or at the screen to observe information displayed.  
2. Printers - Users may leave sensitive printouts, some printers store data locally and can re-print data.  
3. Keyboards/mice - Key loggers may intercept and record key strokes and transmit them, revealing passwords and other sensitive information.  
4. Firmware - Software stored on a ROM chip.  
5. BIOS - Basic input/output system. Contains OS independent primitive instructions that a computer needs to start up and load the OS from disk.  
6. Device firmware also needs limited processing.  

### 3.5 Client-Based Systems. 

1. Client-side attack - Any attack that is able to harm a client, may occur over any protocol. 
2. Applets - Code objects that are sent from a server to a client to perform some action - mini programs.  
3. Local cache - Anything that is temporarily stored on the client for future reuse - see ARP caches, the chapter goes into a ridiculous amount of detail on ARP attacks and DNS cache poisoning. 

### 3.6 Server-Based Systems.  

1. Data flow control - The movement of data between process, between devices, across a network, or over communication channels.  
2. Making sure endpoints are not overwhelmed with traffic - maybe by using a load balancer. 
3. Denial of service attack - Attacking the availability of a resource or system, often by attacking data flow control. 

### 3.6.1 Large-Scale Parallel Data Systems.  
1. Within the arena of multiprocessing or parallel processing there are several divisions. The first division is between symmetric multiprocessing (SMP) and asymmetric multiprocessing (AMP). 
2. The scenario where a single computer contains multiple processors that are treated equally and controlled by a single OS is called symmetric multiprocessing (SMP). 
3. In asymmetric multiprocessing (AMP), the processors are often operating independently of one another. Usually, each processor has its own OS and/or task instruction set, as well as a dedicated data bus and memory resources.  
4. A variation of AMP is massive parallel processing (MPP), where numerous AMP systems are linked together to work on a single primary task across multiple processes in multiple linked systems.  

### 3.6.2 Grid Computing. 
1. Grid computing is a form of parallel distributed processing that loosely groups a significant number of processing nodes to work toward a specific processing goal. Members of the grid can enter and leave the grid at random intervals. The biggest security concern with grid computing is that the content of each work packet is potentially exposed to the world. 

### 3.6.3 Peer to peer - 
1. Share tasks and workloads among peers, like grid computing, but there is no central management system.  

### 3.7 Database Systems Security. 

1. Aggregation - Combining records from one or more tables to produce potentially useful information.  
2. An attacker might be able to take multiple pieces of seemingly innocuous information, and combine them to infer something more dangerous.  
3. Inference - Combining several pieces of non-sensitive information to gain access to information that should be classified at a higher level. 
4. Data mining & data warehousing - Warehouses are large databases, data dictionaries are used for storing critical information about data, mining allows analysts to comb through warehouses and look for correlated information. 
5. Data analytics - The science of raw data examination with the focus of extracting useful information out of the bulk information set. 
6. Big data - Collections of data that have become so large that traditional means of processing aren’t enough. 
7. Large-Scale parallel data systems - Systems designed to perform numerous calculations simultaneously. 

### 3.8 Distributed Systems.  
1. A distributed system or a distributed computing environment (DCE) is a collection of individual systems that work together to support a resource or provide a service.  
2. A DCE typically includes an interface definition language (IDL). An IDL is a language used to define the interface between client and server processes or objects in a distributed system.
3. There are some security issues inherent with DCE. 
Access by unauthorized users. 
4. Masquerading, impersonation, and spoofing attacks of users and/or devices.  
5. Security control bypass or deactivating. 
6. Communication eavesdropping and manipulation. 
7. Insufficient authentication and authorization. 
8. A lack of monitoring, auditing, and logging. 
9. Failing to enforce accountability'. 

### 3.9 High-Performance Computing (HPC) Systems
1. High-performance computing (HPC) systems are computing platforms designed to perform complex calculations or data manipulations at extremely high speeds.  
2. An HPC solution is composed of three main elements: compute resources, network capabilities, and storage capacity. Each element must be able to provide equivalent capabilities to optimize overall performance. 
3. A real-time operating system (RTOS) is designed to process or handle data as it arrives on the system with minimal latency or delay. An RTOS is usually stored on read-only memory (ROM) and is designed to operate in a hard real-time or soft real-time condition. A hard real-time solution is for mission-critical operations and A soft real-time solution is used when some level of modest delay is acceptable.  

### 3.10 Internet of Things
1. Smart devices - Mobile devices that have customization options, apps, on-device or in-cloud AI. 
2. Internet of things - IoT. A class of smart devices that are internet-connected to provide automation, remote control, or AI processing to traditional or new devices. 
3. Often not designed with security in mind. 
4. One possible secure implementation is to deploy a distinct network segment for the IoT equipment, which is kept separate and isolated from the primary network. This configuration is often known as three dumb routers.  
5. Industrial Internet of Things (IIoT) is a derivative of IoT that focuses more on industrial, engineering, manufacturing, or infrastructure level oversight, automation, management, and sensing. 
6. The best means to reduce IoT risk from these options is to keep devices current on updates.  
7. There are several forms of ICS, such as programmable logic controllers (PLCs), distributed control systems (DCSs), and supervisory control and data acquisition (SCADA). In industrial control systems (ICSs), ensuring the availability of real-time control signals is a primary concern.  

### 3.11 Edge and Fog Computing
1. Edge computing is a philosophy of network design where data and the compute resources are located as close as possible to optimize bandwidth use while minimizing latency. 
2. Edge computing is often implemented as an element of IIOT solutions, but edge computing is not limited to this type of implementation. 
3. One potential use for edge devices is the deployment of mini-web servers by ISPs, and Other examples of edge computing solutions include security systems, motion-detecting cameras, image recognition systems, IoT and IIOT devices, self-driving cars, optimized content delivery network (CDN) caching, medical monitoring devices, and videoconferencing solutions. 
4. Fog computing relies on sensors, IoT devices, or even edge computing devices to collect data, and then transfers it back to a central location for processing. 

## 4. Embedded Devices and Cyber-Physical Systems
1. An embedded system is any form of computing component added to an existing mechanical or electrical system for the purpose of providing automation, remote control, and/or monitoring. Embedded systems can be a security risk because they are generally static systems.  
2. A static environment is a set of conditions, events, and surroundings that don't change. Examples of static systems include the check-in kiosk at the airport, an ATM, and often the complimentary guest computer at a hotel or library. 
3. Cyber-physical systems refer to devices that offer a computational means to control something in the physical world. Cyber-physical devices and systems are essentially key elements in robotics and sensor networks. 
4. A microcontroller is a small computer consisting of a CPU, various input/output capabilities, RAM, and often nonvolatile storage in the form of flash or ROM/PROM/EEPROM. Examples include Raspberry Pi, Arduino, and a field-programmable gate array (FPGA). Arduino is a microcontroller that can be used to perform automated tasks. A field-programmable gate array (FPGA) is a flexible computing device intended to be programmed by the end user or customer.

## 6. Virtualized Systems
1. Type 1 hypervisor - Native or bare-metal hypervisor, there is no host OS, the hypervisor installs directly on the hardware. 
2. Type 2 hypervisor - Hypervisor software is installed on top of another OS. 
3. Cloud storage - Using storage provided by a cloud vendor to host data for an organization. 
4. Elasticity - The flexibility to expand or contract based on need. 
5. Scalability is the ability to take on more work or tasks. 
6. Platform as a service - PaaS. Providing a computing platform and software stack as a virtual service
7. Software as a service - SaaS. Providing on-demand online access to software applications without need for local installation. 
8. Infrastructure as a service - IaaS. Providing on-demand outsourcing options for operating solutions
9. Hosted solution - A deployment concept where the organization must license software and then operates and maintains the software - the hosting provider takes care of the hardware that supports the organization’s software. 
10. Private cloud - Service within a corporate network and isolated from the internet, internal use only
11. Public cloud - Services are accessible to the general public over an internet connection, usually paid for with subscriptions or pay-per-use, could be free. Data is separated and isolated from other customers, but the overall purpose of the cloud is the same for all customers. 
12. Hybrid cloud - A mix of public and private. 
Community - A shared environment used and paid for by a group of users or organizations for shared benefit
13. A virtual application or virtual software is a software product deployed in such a way that it is fooled into believing it is interacting with a full host OS. 
14. A virtualized network or network virtualization is the combination of hardware and software networking components into a single integrated entity. 
15. Software-defined everything (SDx) refers to a trend of replacing hardware with software using virtualization. 
16. Software-defined visibility (SDV) is a framework to automate the processes of network monitoring and response. 
17. Server sprawl or system sprawl is the situation where numerous underutilized servers are operating in your organization's server room.  VM sprawl occurs when an organization deploys numerous virtual machines without an overarching IT management or security plan in place. 
18. VM escaping occurs when software within a guest OS is able to breach the isolation-protection provided by the hypervisor to violate the container of other guest OSs or to infiltrate a host OS. 

## 7. Assess and Mitigate Vulnerabilities in Mobile Systems
1. Malicious insiders can bring in malicious code from outside, or exfiltrate information using mobile devices
Eavesdropping is possible. 
2. Security-Enhanced Android (SEAndroid) is a security improvement for Android. 
3. Unified endpoint management (UEM) is a type of software tool that provides a single management platform to control mobile, PC, IoT, wearables, ICS, and other devices. UEM is intended to replace MDM. 
4. Full device encryption - Encrypt the entire device so that if it is lost, the data should be safe if the device is not unlocked. 
5. Remote wiping - The ability to sanitize a device if it is lost or stolen, without having physical access to the device. 
6. Lockout - When a user fails to provide their credentials after repeated attempts, the device may implement a cooldown period, or become locked forever.  
7. Screen locks - Designed to prevent someone from casually picking up a device and using it. 
8. GPS - Global Positioning System. Can be used to track the location of devices. 
9. Application control - Device management solution that allows administrators to limit which applications can be installed on a device. 
10. Storage segmentation - Artificially compartmentalizing types of data on a storage medium - ex. separating the device OS and installed apps. 
11. Asset tracking - Management process used to maintain oversight over an inventory.  
12. Inventory control - Hardware asset tracking, and the concept of using a mobile device as a means of tracking inventory in a warehouse. 
13. Mobile device management - Software solution for managing mobile devices over a communications channel
14. Device access control - Blocking unauthenticated access to a device. 
15. Removable storage - Should also be encrypted, if allowed. 
16. Disabling unused features - Remove apps and features that aren’t needed for business tasks or common personal use. 
17. Sideloading is the activity of installing an app on a device by bringing the installer file to the device through some form of file transfer or USB storage method. 
18. Key management - Most crypto failures are from poor management, not poor algorithms. Have good key selection, based on quality random numbers. 
19. Credential management - Storage of credentials in a central location. 
20. Geotagging - Using GPS to embed the location of a photo or other file. 
21. Geofencing is the designation of a specific geographical area that is then used to implement features or trigger settings automatically on mobile devices. 
22. Application allow-listing - Prohibiting unauthorized software from executing. Deny by default, implicit deny. 
23. BYOD - Bring your own device (BYOD) is a policy that allows employees to bring their own personal mobile devices to work and may allow them to use those devices to connect to business resources and/or the Internet through the company network. 
24. COPE - Corporate-owned, personally enabled (COPE) is a mobile policy where the organization purchases devices and provides them to employees. 
25. COMS - A corporate-owned mobile strategy (COMS) or corporate-owned, business-only (COBO) strategy is when the company purchases the mobile devices that can support security compliance with the security policy. 
26.CYOD - The concept of choose your own device (CYOD) provides users with a list of approved devices from which to select the device to implement. 
27. Data ownership - Commingling personal data and business data is likely to occur when using personal devices for business tasks, or vice versa. 
28. Segmentation can help, isolation
29. Acceptable use policy - Critical to define what is and is not acceptable usage while mixing personal activities and business tasks. 
30. Firmware over-the-air (OTA) updates are firmware updates that are downloaded from the telco or vendor over-the-air. 

## 8. Essential Security Protection Mechanisms
Software should not be trusted
Layering - Implement a structure similar to a ring model
Abstraction - Fundamental to object oriented programming, users of an object don’t need to know the details of how the object works
Data hiding - This is different from security by obscurity which is a bad practice. This is putting data in a location that it is not unnecessarily visible.
Process isolation - Requires the OS to provide separate memory spaces for each process’s instructions and data
Hardware segmentation - Similar to process isolation in purpose, but for hardware

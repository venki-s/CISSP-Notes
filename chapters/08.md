## 1. Secrure Design Principles

### 1.1 Objects and Subjects.  
1. Subject - The user or process that makes a request to access a resource. 
2. Object - The resource a subject wants to access. 
3. Transitive trust - If A trusts B, and B trusts C, then A inherits trust of C through B. 
4. May enable bypassing of restrictions or limits between A and C. 
5. Closed and Open Systems. 
6. Closed system - Designed to work well with a narrow range of other systems. 
7. Open system - Designed using agreed-upon industry standards. 
8. This is different than closed/open source. 
9. Attacking a closed system is harder. 
10. Declassification is the process of moving an object into a lower level of classification once it is determined that it no longer justifies being placed at a higher level.  
11. Perturbation is the use of false or misleading data in a database management system to redirect or thwart information confidentiality attacks.   
12. Noninterference is the concept of limiting the actions of a subject at a higher security level so they do not affect the system state or the actions of a subject at a lower security level.  

### 1.2 Techniques for Ensuring CIA. 
1. Confinement - Allows a process to read from and write to only certain memory locations and resources. 
2. Bounds - Processes are assigned an authority level. 
3. Bounds of a process consist of limits set on the memory locations and resources it can access. 
4. Isolation - Enforcing access bounds. Used to protect the operating environment, the kernel of the OS, and other applications.  
5. Controls - Uses access rules to limit the access of a subject to an object. 
6. MAC - Mandatory access control. 
7. DAC - Discretionary access control. 
8. Each subject has attributes that define clearance/authority/access to resources. 
9. Each object has attributes that define it’s classification. 
10. Trust and Assurance - Security issues should not be added on as an afterthought.  
11. Trusted system - One where all protection mechanisms work together to process sensitive data for different users while maintaining a secure computing environment.
12. Assurance - The degree of confidence in the satisfaction of security needs
13. When change occurs, the system needs to be reevaluated. 
14. Fail-Open: Allows access during failure → Protects People (Physical) and Availability (Digital).
15. Fail-Safe: Enters a predefined safe state during failure → Protects People or Assets, depending on design.
16. Fail-Closed: Denies access during failure → Protects Assets, Confidentiality & Integrity.
17. Fail-Secure: Remains locked during failure → Protects Assets, Confidentiality & Integrity
18. Some other models that fall into the information flow category build on the notion of inputs and outputs between multiple systems. 
    a. Cascading: Input for one system comes from the output of another system.  
    b. Feedback: One system provides input to another system, which reciprocates by reversing those roles (so that system A first provides input to system B and then system B provides input to system A).  
    c. Hookup: One system sends input to another system but also sends input to external entities.  

## 2. Security Models

### 2.1 Bell-LaPadula Model.  

1. US Department of Defense developed in 1970s.  
2. Concerned with protecting classified information.  
3. A subject with any level of clearance can access resources at or below its clearance level.  
4. Prevents leaking or transfer of classified information to less secure clearance levels.  
5. Does not address integrity or availability
6. No read up (simple property)
7. No write down (star property)
8. Uses an access control matrix (discretionary property - need to know)

### 2.2 Biba Model.  

1. Integrity is more important than confidentiality
2. Also built on state machine concept, based on information flow, and is multilevel
3. Very similar to Bell-LaPadula, except inverted
4. No read down (simple property)
5. No write up (star property)

### 2.3 Clark-Wilson Model
1. Does not use lattice structure, but rather uses access triple control
   a. Subject
   b. Program/transaction
   c. Object
2. Objects are accessed only through programs
3. Constrained data item - CDI. Any data item whose integrity is protected by the security model
4. Restricted interface model - Elements of an interface are limited based on a subjects rights and authorization
5. Brewer and Nash Model (aka Chinese Wall)
6. Changes dynamically based on a user’s previous activity
7. Chinese Wall model - Creates a class of data that defines which security domains are potentially in conflict and prevents subjects with access to one domain that belongs to a specific conflict class from access any other information in the conflict class
8. Protects from conflicts of interest

## 3 Select Security Controls Based On Systems Security Requirements.  

1. Need a tested and technical evaluation.  
2. Need a formal comparison of its design and security criterial.  
3. Sometimes you may need a trusted third party to provide a seal of approval.  
4. Trusted Computer System Evaluation Criteria - TCSEC. Standards to attempt to specify minimum security criteria for various categories of use.  
5. Classes and required functionality. 
   a. D - Minimal protection. 
   b. C1 - Discretionary protection. 
   c. C2 - Controlled access protection. 
   d. B1 - Labeled security. 
   e. B2 - Structured protection. 
   f. B3 - Security domains. 
   g. A1 - Verified protection. 

### 3.1 Common Criteria. 

1. The Common Criteria process is based on two key elements: protection profiles and security targets. Protection profiles (PPs) specify the security requirements and protections for a product that is to be evaluated ( target of evaluation - the TOE), which are considered the security desires, or the “I want” of a customer. Security targets (STs) specify the claims of security from the vendor that are built into a TOE. 
2. Represents a global effort that is similar to TCSEC in function/purpose.    
3. Assurance levels.  
   a. EAL1 - Functionally tested. 
   b. EAL2 - Structurally tested.  
   c. EAL3 - Methodically tested and checked.  
   d. EAL4 - Methodically designed, tested, and reviewed. 
   e. EAL5 - Semi-formally designed and tested. 
   f. EAL6 - Semi-formally verified, designed, and tested. 
   g. EAL7 - Formally verified, designed, and tested. 
4. Industry and International Security Implementation Guidelines.  
5. Payment Card Industry Data Security Standard (PCI DSS). 
6. International Organization for Standardization (ISO). 
7. Certification - Comprehensive evaluation of security features of an IT system. 
8. Accreditation - A formal declaration by the designated approval authority that an IT system is approved to operate in a particular security mode. Often an iterative process. 
9. The assessment and assignment of an ATO is performed by an authorizing official (AO). A typical ATO is issued for 3 years and must be reobtained whenever one of the following conditions occurs:   
   a. The ATO time frame has expired.  
   b. The system experiences a significant security breach.  
   c. The system experiences a significant security change.  

### 3.2 Understand Security Capabilities of Information Systems
1. Virtualization - Used to host one or more operating systems within the memory of a single host computer.  
2. Trusted Platform Module - TPM. Specification for a cryptoprocessor chip on a mainboard, and the general name for implementation of the spec Stores and processes cryptographic keys.  
3. Hardware security module - HSM. A cryptoprocessor used to manage/store digital encryption keys, accelerate crypto operations, support faster digital signatures, improve authentication.  A TPM is an example of a hardware security module (HSM).   
4. Interfaces - Implemented with an application to restrict what users can do or see based on their privileges
5. Fault tolerance - The ability of a system to suffer a fault but continue to operate

The assessment and assignment of an ATO is performed by an authorizing official (AO).
